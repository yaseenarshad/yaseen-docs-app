# Regression list

The one list of everything Yaseen Docs does that a change must not lose (YAZ-2171, seeded from the YAZ-2131 scope inventory). Every row has a stable ID. A PR cites the IDs it touches, and each one is proved by the automated test named here, or by walking its hand steps.

- **A** = a Playwright-Electron spec in `desktop/e2e/` (86 specs; run with `npm run e2e`).
- **U** = a unit or jsdom suite (run with `npm test`).
- **M** = hand steps, listed under [Hand scenarios](#hand-scenarios). Only what automation cannot drive lives there.

Each **A** spec was run, hidden, on 21 Oct 2026 for YAZ-3102: all 326 steps pass, also the steps that were written without being run (the folder specs, `tabs`, `ids`, `search`, `lenses`, `tableOfContents`, `sectionIndent`, `settings` and the others). `tableOfContents` step 2 checks the path after a turn of the wheel within the 1500 ms that the path stays, so a very slow computer can fail there.

The end-to-end proof of E22, F1, F3, F4, F5, F10 and G1 is to be rebuilt under YAZ-2459. Where one of those cells says there is no **A** proof, or names what its **A** proof leaves out, only the **U** suites it lists stand behind that part.

Add a row when a feature ships. Never delete one unless the feature is removed on purpose, and cite the ticket that removed it.

## PR checklist

- [ ] `npm test` green
- [ ] `npm run typecheck` green
- [ ] the size/integrity budget gate green, with its numbers pasted
- [ ] `npm run e2e` green once; three runs in a row for a release candidate
- [ ] every REGRESSION row this change touches is re-proved (its spec ran, or its hand steps were walked) and listed in the PR body

## Hand scenarios

### E24 Spelling

1. Type a misspelt word (`recieve`) in a note. It gets the red squiggle.

### E28 Page settings and line numbers

The dev app (`npm run dev`) will do for steps 1 to 13, on an isolated profile (`YASEEN_DOCS_USER_DATA_DIR`) with a scratch vault. Write one note in a text editor, not in the app: 4 lines of frontmatter, then an H1, an H2 and an H3, a paragraph of three lines, `-` bullets three levels deep, two or three blank lines between some blocks, a quote, a fenced code block with a language and one long line with no space in it, a table, a rule and an image. These are the cases of YAZ-2643 that need eyes, a real layout or a built app (S1 to S9, S11 to S13, S21 to S23, S25, S26, S28, S47, S49 to S54, S56, S57, S66, S72, S74, S75, S78, S79), and the audit items A15, A16 and C1.

1. Open the note. Its top row reads: the cog, the zoom pill, the sync chip, the save chip. The cog is as high as the pill. Hover it: its background changes. Press Tab until it has the focus: the accent ring shows. Do this in the light and in the dark theme. A folder page, a PDF and an image have no cog; a code file has the code tab's own (E46).
2. Click the cog. The menu opens below it, with its right edge on the cog's right edge. It shows "Line numbers", "Section indent" ([E34](#e34-section-indent)), then "Heading levels", "Table of contents" and "TOC made from:" with Auto, Headings and Bullets (YAZ-2700, [E31–E33](#e31e33-the-table-of-contents-the-heading-level-tag-and-the-toolbar-order)), a divider, and "N words" and "N characters" in grey. Click "Line numbers": the row gets the check mark and the accent background, and the menu stays open. Press Esc: the menu closes, the focus ring is on the cog, and the sidebar did not take the focus. Open the menu again and click in the note: the menu closes.
3. With the numbers on, the numbers are in a lane of their own, left of the page's margin, small, grey and monospace. They make ONE straight column, aligned on the right: the same column for the paragraph, each heading, a bullet at each of the three levels, the quote, the code block, the table and the rule. The paragraph of three lines shows its range on one line, as `8–10`, and so do the code block (its opening fence to its closing fence) and the table (its header row to its last row). A block of one line shows one number. Each range is whole: no part of it is cut off, and nothing is drawn over it.
4. Each number or range is on the first line of its block: on the first of the three lines of the paragraph, and on the text line of the H1, the H2 and the H3. The table's range is on its header row. The rule's number is on the line.
5. Look at a block near the bottom of the window and turn the numbers off and on three times. Each time the numbers come on, the whole page slides right by the lane: the title, the properties, the body and the blocks below it move together and stay one column. The slide is 64px in a window that the note's column fills, and half of that in a wide window. Each time the numbers go off, the page slides back to where it was. A line of text can wrap again; nothing else changes. Hover a paragraph, then a parent bullet: the drag handle is beside the number, not on it, and the fold arrow does not touch it.
6. Open the same file in a text editor that shows line numbers. For the H1 below the frontmatter, a nested bullet, the block below the blank lines, the fence of the code block and the header row of the table: the number on the page is the line in the text editor. For the paragraph of three lines, the code block and the table: the second number of the range is the block's last line in the text editor. Inside the code block, its own line numbers are the lines of the text editor too: the first code line reads one more than the fence. Turn the numbers off: the code block reads 1, 2, 3. Turn them on again.
7. Make the window narrow, so that the note's column fills it. Set the zoom to 50%, then 150%, then 300%. At each zoom the numbers and the ranges are whole and in their lane, they make one column, they are on the first line of their block, and they have the same size as at 100%: only the text scales. Back at 100%, in a note of 1,000 lines or more, the left part of a long range (`1207–1210`) or of a 5-digit number can be cut off in this narrow window (accepted). Note the longest range that is whole.
8. The code block, with the numbers on: its corners are rounded as before. The long line wraps inside the block and nothing runs out of it. The language menu opens, and a pick changes the language. Click in the code block and type a new line: the caret stays where you type, and the lines under the new one count one more at once. Put a second, long code block at the end of a long note, turn the numbers on at the top and scroll down to it: its own line numbers are lines of the file when it comes into view.
9. With the numbers on, select text across three blocks with the mouse: the selection looks as before, and no number is in it. Copy it and paste it in a text editor: the text has no numbers. `⌘F` highlights its matches. Hover a paragraph: the block handle is at its usual place and drags the block. Hover a parent bullet and the H2: each fold arrow is at its usual place and works. Hover the image: its handles are on the image. Hover the table: its handles are at their usual places.
10. Fold a parent bullet, then the H2's section. The numbers of the hidden blocks are gone, and the visible numbers jump over them.
11. Put the caret at the end of a bullet, press Enter and type a word. The numbers of the other blocks stay while you type. The new bullet, and the bullet you split, have no number at first. Each gets its number about half a second after the last key. Type a new code block (three backticks, Enter, two lines of code): it has no number, and its own lines read 1, 2 at first. About half a second after the last key it has its range, and its own lines are lines of the file.
12. In the text editor, add two lines above the H1 and save. The note reloads, and each number below is 2 more.
13. Open a second note in a new tab: its numbers are off. Go back to the first tab: its numbers are still on. Open the first note in the right panel: that copy has its own switch, and it is off. Close the first tab and open the note again: the numbers are off. The menu bar and the settings dialog have no item for line numbers, and no key turns them on.
