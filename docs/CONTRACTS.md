## Bridge API (`window.yaseenDocs`, locked in GRO-2153 — Desktop A1)

The desktop app has no HTTP server (GRO-2095 D2): the renderer is sandboxed and calls the typed bridge the preload installs; `ipcMain.handle` answers from the main process (GRO-2157 deleted the server and every HTTP path). All paths are absolute POSIX paths; no jail — any absolute path is allowed. Every method rejects with a plain `BridgeError { code, message, path?, mtime? }` (`BridgeErrorCode` in `shared/types.ts`, plus `CONFLICT` which carries the disk mtime); the client's `api.ts` wraps it in `BridgeRequestError` (same fields) so the renderer can `instanceof` it.

| Bridge | Notes |
|---|---|
| `tree(root)` | `TreeResponse` — recursive; only vault files: `.md`/`.markdown` (`kind: 'markdown'`) and `.base` (`kind: 'base'`, GRO-2123); every dir shows, vault files or not (GRO-2022); dot-entries and `node_modules` skipped; dirs before files, each sorted case-insensitive. Missing / not a dir → `NOT_FOUND` / `NOT_A_DIRECTORY` |
| `readFile(path)` | `FileResponse` — raw UTF-8 content incl. frontmatter; `.md`/`.markdown`/`.base` only (else `UNSUPPORTED_EXTENSION`); `TOO_LARGE` above 10 MiB |

Bases (GRO-2097) adds its methods to `YaseenDocsApi` additively (`index(root)` and `readAsset(root, ref)` above), never routes.

Notes
- Folder picking (client, `usePickFolder`): the sidebar's "change" and the Welcome screen's Open folder… call `pickFolder()`; `{ path }` → set root + push to recents, `{ cancelled }` or a rejection → nothing. No dialog ever opens by itself — a window with no folder shows the Welcome screen (C2, GRO-2164). One dialog in flight at a time; the trigger buttons are disabled meanwhile. There is no in-app folder browser.
- Main-process writes trigger `change` events on the watcher; the client must ignore events for a path whose mtime equals the mtime it just received from its own `writeFile` (echo suppression).
- Auto-save: client debounces 500 ms after last `markdownUpdated`, also flushes on file switch / the close flush handshake (`window.onFlush` — GRO-2158/2160 — is what guarantees the last save; `beforeunload` is best effort). Only content that differs from the last loaded/saved markdown is saved (Crepe's first serialisation is a normalised rewrite and is never written on its own). Frontmatter-only external changes absorb silently (GRO-2186): an incoming `change` whose BODY matches the last loaded/saved body just replaces the autosave baseline — no reload, no conflict bar — so unsaved body edits and the caret survive a base's property write (see "Cell editing").
- Desktop tests run chokidar with `CHOKIDAR_USEPOLLING=1` (see `desktop/vitest.config.ts`): on macOS libuv starts the FSEvents stream asynchronously, so a write right after `ready` can be missed; polling makes the tests deterministic.

## App state (`yaseendocs.json`, main-owned — GRO-2159, D9)

One user-global JSON file owned by the main process: `app.getPath('userData')/yaseendocs.json` = `~/Library/Application Support/Yaseen Docs/yaseendocs.json` (`app.setName('Yaseen Docs')` runs before anything reads userData; `--user-data-dir=<dir>` relocates it, which is how the Playwright checks seed state). Renderer web storage is not used at all. The renderer never touches the file: it reads a cache (`storage.ts` in client lib, filled by `storage.init()` before the first render) and writes through the targeted `state.*` mutators; `desktop/src/main/store.ts` owns the file. Nothing here is ever written into the vault or the markdown.

| Key | Shape | Rules |
|---|---|---|
| `version` | `1` | anything else → the file is treated as corrupt (see below) |
| `settings` | `SettingsState` `{ lineSpacing, blockGap, bulletThreading, threadWidth, threadColor, theme, newNoteLocation, newNoteFolder }` | global: one value for every folder and window; validated field by field on load (`threadWidth` ∈ 1/2/3, `threadColor` `#rrggbb` or null, `theme` ∈ system/light/dark — default `system`, so a pre-K file just gains it; `newNoteLocation` ∈ root/current/folder — default `root` — and `newNoteFolder` a root-relative path per `isValidNewNoteFolder` (`''` = the vault root; no leading/trailing `/`, no empty/`.`/`..` segments) — defaults, so a pre-C2 file just gains them), an invalid field falls back to `DEFAULT_SETTINGS`; `setSettings` takes a complete valid object (else `BAD_REQUEST`). `newNoteLocation`/`newNoteFolder` (Files & Links, Links C2- — GRO-2240) are the settings-cog "Default location for new notes" control (Obsidian's three options; the folder input shows only for `folder` and validates on commit — invalid keeps the stored value) driving where a bare unresolved `[[link]]` creates its page (rule 23); the setting is GLOBAL but `newNoteFolder` is interpreted per-vault against each window's root. `theme` (Appearance, Desktop K — GRO-2218) is the settings-cog System/Light/Dark control: main mirrors it into `nativeTheme.themeSource` before the first window exists and on every change (`desktop/src/main/theme.ts`; new windows also get a matching `backgroundColor`, so no white flash on dark launches), and each renderer resolves it (`system` follows `prefers-color-scheme` live) to `data-theme="light"\|"dark"` on `<html>` — app.css's `[data-theme='dark']` token block — while swapping Crepe's frame/frame-dark var blocks in one managed `<style>` (`client/src/editor/crepeTheme.ts`, CSS-only: the open editor never remounts) |
| `sidebarCollapsed` | `boolean` | global; non-boolean → `false` |
| `recents` | `RecentRoots` `[{ path, lastOpened }]` | most-recent first, de-duplicated by path, max 10 (`pushRecent(path)`, absolute path); wrong shape → `[]` |
| `windows` | `WindowEntry[]` `{ id, root, file, tabs, bounds: { x, y, width, height } }` | one entry per open window, reopened on relaunch with bounds clamped to a live display (see "Multi-window"); malformed or duplicate-id entries dropped on load; `upsertWindow` replaces by id or appends; an entry is removed when its window closes — unless the app is quitting (⌘Q, or the last window closing, which quits), so relaunch restores the same windows. `tabs` (GRO-2232) = the window's open tabs, absolute paths left→right, with `file` doubling as the ACTIVE tab — `normalizeTabs` repairs both on load and on every `setIdentity` (see "Multi-window": Tabs) |
| `folders[root]` | `FolderState` `{ expanded: string[], lastFile: string \| null, folds: { [file]: string[] }, baseGroups: { [basePath::viewName]: string[] } }` | per folder; `setFolder(root, { expanded?, lastFile? })` merges and creates the entry with defaults when missing (other keys ignored); `setFolds(root, file, keys)` replaces one file's collapsed outline fold keys (max 500; an empty list removes the file entry, the folder entry stays); `setBaseGroups(root, key, collapsed)` does the same for one base view's collapsed group keys (max 200, 4C — GRO-2137); invalid lists dropped on load |

Write semantics: every mutation updates memory, notifies `onChange` listeners synchronously and schedules one debounced (150 ms) atomic write (`<file>.tmp-<rand>` + rename, pretty-printed JSON, parent dir created on demand); `flush()` writes at once and `before-quit` holds the quit until it lands (`event.preventDefault()` + `app.exit(0)`), so nothing is lost on ⌘Q. A file that is unparsable, not an object or not `version: 1` is moved to `yaseendocs.json.corrupt-<epoch>` and the defaults are used — the bad file is never overwritten silently. Unknown top-level keys are dropped on load.

Live broadcast: after any change — from any window, or from main itself (window upserts) — every live `BrowserWindow` gets `state:changed` with the whole new state; the preload surfaces it as `state.onChange`, the client cache replaces itself and `storage.subscribe` listeners fire (`App` re-reads settings and `sidebarCollapsed`). A window's own writes update its cache optimistically and do not fire its subscribers until the echo arrives.

Per-window identity: main loads each window as `<renderer>?win=<id>` and keeps a `webContents.id → window id` registry (`desktop/src/main/windows.ts`). `window.identity()` answers `{ id, root, file }` from `windows[]` for the calling window (`BAD_REQUEST` for an unregistered sender, `NOT_FOUND` once the entry is gone); `window.setIdentity({ root?, file? })` merges into that entry (absolute paths or null; `id` and `bounds` cannot be changed this way). On the client, `storage.getRoot()` IS the identity's root; `setRoot` also clears `file` when the root changes; `setLastFile(root, file)` records both the folder's `lastFile` (for the next time that folder opens) and the window's `file` (what is open now).

## Menus & shortcuts (B3 — GRO-2161)

The menu bar is a pure template (`desktop/src/main/menu.ts`, `buildMenuTemplate(inputs, handlers)`) so structure, accelerators and roles unit-test without Electron; `main/index.ts` applies it (`Menu.buildFromTemplate` + `setApplicationMenu`) and rebuilds it ONLY when `AppState.recents` actually changed (`subscribeMenuRebuild` compares by reference — store snapshots reuse untouched sub-objects). Item ids are stable (`menu.file.new-window`, `menu.file.open-recent.<i>`, …) so a live check (Playwright) can drive them via `Menu.getApplicationMenu().getMenuItemById(...)`.

## Multi-window (D3/D6 — GRO-2160/2167/2168/2169)

The window manager (`desktop/src/main/windows.ts`) is Electron-free — `main/index.ts` injects window construction and display geometry as a `WindowHost`, so everything below runs under vitest with fakes.

- **Restore** (D3): on launch, one window per `AppState.windows` entry; an empty state seeds a single Welcome window (`root: null`). Restored bounds are clamped fully inside the display work area they overlap most (fully off-screen → the nearest one; oversized → shrunk to fit) — so a window from an unplugged display always lands somewhere visible. Bounds changes (`move`/`resize`) are committed to the state debounced (250 ms per burst — one `state:changed` per drag).
- **Duplicate** (GRO-2167): `⌘⇧N` / `window.duplicate()` — same folder, same file, same TABS (the copy carries the whole set), fresh id, bounds cascaded +24 px and clamped at the display edge. A Welcome window duplicates to another Welcome window.
- **Open beside** (D2, GRO-2168): a file row's context-menu "Open in new window" → `window.open({ root, file })` — an independent window on the same folder with that file open. Open Recent's ⌥-click and deep-link routing use the same `openWindow` path (default bounds, clamped). ⌘-click on a sidebar file row is NOT this gesture any more: since I3 (GRO-2235, locked) it opens a background tab in the SAME window — see Tabs below.
- **Tabs** (GRO-2232/2234/2235): a window's open files are `WindowEntry.tabs` (absolute paths, left→right) with `file` doubling as the ACTIVE tab. Invariants, repaired by `normalizeTabs` on load and held at the IPC boundary on every `setIdentity`: `file ∈ tabs` whenever non-null (a legacy entry without `tabs` becomes `[file]`), `tabs: []` ⇔ `file: null`, and `tabs` de-duplicated by path — ONE editor per path per window, so opening an already-open file (sidebar click, deep link, ⌘-click) activates its tab and never duplicates it. After boot the RENDERER owns the model (`client/src/tabs/useTabs.ts`) and mirrors every change down as ONE explicit `setIdentity({ tabs, file })` — never a `{ file }`-only patch. Gestures: a sidebar click or routed deep link opens in the CURRENT tab (a link never spawns a tab or window when its file's tab exists — it activates it); ⌘-click a sidebar file row appends a BACKGROUND tab at the end of the strip without activating it; tabs drag-to-reorder; middle-click or ✕ closes. The ⌘W ladder: close the active tab (its right neighbour takes over, else the left) → closing the last tab leaves the empty state with the window ALIVE → ⌘W with zero tabs closes the WINDOW through the real close path. Restore/relaunch reopens every tab with the stored active one on top; only VISITED tabs mount editors (a background tab's editor lazy-mounts on first activation). Activating a tab whose file vanished on disk closes it through the sidebar's `onFileMissing` path (confirmed against a fresh tree); background tabs are never probed.
- **Single instance** (GRO-2160): `requestSingleInstanceLock` — a second launch quits itself; the first instance gets `second-instance`, routes any `yaseendocs://` URLs in its argv (E1), else focuses a window.
- **Close/quit flush handshake** (GRO-2160): `close` is ALWAYS intercepted — main commits the bounds, sends `app:flush`, the renderer flushes its autosaves (`window.onFlush` listeners) and acks `app:flushed`, then main `destroy()`s the window; a hung save can never block close (hard 5 s cap). A user close removes the window's state entry; the LAST window closing quits (`window-all-closed`), and quits — like ⌘Q's sequential flush of every window — keep the entries so relaunch restores them.
- **Same file in N windows** (GRO-2169 — D6/D9/A4): no dedicated sync channel — the disk-change path IS the sync. A window's save lands on disk → the shared watcher emits `change` to every window → each other window reloads silently when clean, or shows the conflict bar (Reload / Keep mine) when dirty. Echo suppression is per window: each window's own `Autosave` controller holds the mtime from ITS last `writeFile` response and only drops events matching that mtime (client `editor/Editor.tsx` / `bases/BaseHost.tsx`), so window A's save is never mistaken for window B's echo. Folds are shared per file through the app state (`folders[root].folds`) — last writer wins, applied the next time the file is opened; live windows are NOT re-folded. Zoom is per window and in-memory only, never persisted. One chokidar per folder in main, shared by every window and subscription (`desktop/src/main/fs/watchers.ts`); it closes when the last subscriber leaves.

## Links (E1/E2/E3 — GRO-2171/2172/2173)

- **Format** (E1, locked D7): a note's shareable URL is its `yaseendocs://` file link — path-only, absolute, percent-encoded (`yaseendocs:///Users/me/vault/My%20note.md`), no vault id; an optional `?root=` (also a percent-encoded absolute path) overrides which folder it opens under. `shared/links.ts` (`fileLink`/`parseFileLink`) is the ONE encoding, shared by main's parser and the client's generator; `encodeURI` plus `#` and `?` encoded on top, so either never truncates the path.
- **Copy link** (E3): the sidebar context menu's "Copy link" on a FILE row puts exactly `fileLink(path)` on the clipboard (folders and blank space get no item).
- **Routing** (E1): a link — clicked anywhere (`open-url`), handed over by Finder's Open With (`open-file`, E2 — the plain path is re-encoded through `fileLink` and rides the same pipeline), or in a second launch's argv — routes identically (`resolveLinkTarget`): (1) the open window whose root contains the file — most specific root wins, Welcome windows never match — is focused and switches to it (`link.onOpenFile`); (2) else a new window opens on the most recent recents folder containing it (`?root=` pins the effective root instead when it contains the path); (3) else on the file's parent directory. Links queue until the windows are restored on cold start (`linkQueue.ts` — macOS fires `open-url` before `ready`), so hot and cold behave the same.
- **Failure surface** (E1): a non-markdown or missing target — or an unparsable link — focuses a live window and shows the passive in-window notice (`link.onNotice`), never a dialog.
- **In-window wiki-link navigation** (Links C, GRO-2192) is RENDERER-LOCAL: clicking a `[[wikilink]]` in the editor drives this window's own tabs API (`openCurrent` / `openBackground`, Editor rule 23) — no IPC, no main-process involvement; the manager's `routeToFile` (the Routing bullet above, `windows.ts`) stays the ONLY path that focuses another window or creates one.
- The in-app `#/abs/path.md` hash (Editor rule 17) is separate and unchanged.

## Editor rules (client)

1. **Frontmatter**: on load, `splitFrontmatter(content)` → `{ frontmatter, body }`; only `body` goes into Crepe. On save, write `frontmatter + getMarkdownForSave(crepe)`. Frontmatter is re-prepended byte-identically (Crepe would otherwise turn `---` YAML into `***` + paragraph + setext heading underline).
2. **Crepe construction**: always via `createCrepe()` — features come ONLY from `src/editor/featureConfig.ts` (`ENABLED_FEATURES` / `DISABLED_FEATURES`, every `CrepeFeature` classified; ImageBlock, TopBar, AI off; `featureConfig.test.ts` asserts the running editor loads exactly the allowlist), list_item content `block+` (extended from GFM task item schema), `markdownUpdated` listener wired.
3. **Save post-processing**: `postProcessMarkdown()` un-escapes `\[\[` → `[[` (wikilinks/embeds).
4. **Replacing content in a live instance** (external change / Reload): `setMarkdown(crepe, md)` → `replaceAll(md, true)` from `@milkdown/kit/utils`, keeping focus and caret. TAB SWITCHES never remount (GRO-2234): every VISITED tab keeps its editor mounted in its own layer, inactive layers hidden via `visibility: hidden` — never `display: none`, which would reset the scroller's scrollTop — so scroll position, caret, undo history and the unsaved buffer all survive a switch. Opening a DIFFERENT file in the same tab still remounts the Crepe host (`key={path}`): the old file's editor unmounts (→ autosave flush) and the previous file stays on screen until the next one has loaded.
5. **Outline folding** (GRO-2011): `createOutlineFolding()` (`src/editor/outline/`) is registered in `createCrepe()`. Parent `list_item`s (those owning a nested `bullet_list`/`ordered_list`) get a widget `<button class="outline-toggle" aria-expanded>` at the start of their content (one stroked SVG chevron sized by `--fold-chevron-size`, default 14px, rotated −90° via CSS when collapsed — GRO-2093; the 18px box is unchanged so strip/gate geometry holds); collapsing adds `data-outline-folded="true"` to EVERY nested list of the item (CSS `display:none`) — mixed markers at one indent (`* a` then `- b`) are unified on load (rule 8, GRO-2112); should sibling lists still arise (e.g. bullet + ordered), all of them fold (GRO-2031). Toggles are metadata-only transactions (`tr.docChanged === false`) — the listener never fires `markdownUpdated`, `getMarkdownForSave()` is unchanged, and the file's mtime is untouched. Fold keys = FNV-1a hash of the item's first-block text + occurrence index (`outlineFoldKeys.ts`), persisted via `storage.getFolds/setFolds`. Fold transactions carry one of: a position (toggle), `fold-all` / `unfold-all`, `{ set, collapsed }` (GRO-2107 guide-line click: any expanded → collapse all, else expand all), `undo-fold`; the multi-item ones remember the previous collapsed set so ⌘Z reverts them as one step.
6. **Accepted lossy normalisation** (standard remark-stringify behaviour; content preserved, formatting normalised): `-`/`+` bullets → `*` (alternating `-` for adjacent sibling lists), tabs → 2-space indent, `1)` ↔ `1.` ordered markers swap/renumber, setext → ATX headings, two-space hard breaks → `\`, trailing whitespace stripped, `___` → `***`, indented code → fenced, tables re-padded, lazy blockquote continuation gets `> `, `_`/`*`/`[`/`=`/`&` escaped in text where ambiguous, bare URLs/emails → `<autolink>`, file always ends with a single `\n`. First save of an untouched file WILL rewrite the file in this normalised form.
7. **Outliner keymap** (GRO-2012, `src/editor/outline/listCommands.ts`, registered in `createCrepe()` with keymap priority 100): Tab = indent (no-op on a first sibling — never inserts spaces), Shift-Tab = outdent (level 1 → paragraph; following siblings nest under the lifted item), Enter at the end of a parent item = new FIRST child (after the subtree when the parent is folded), Enter on an empty item = outdent / leave the list, Backspace at the start of an item = join into the previous paragraph (empty parent: children take its place; non-empty parent: no-op). Multi-item selection + Tab/Shift-Tab moves all selected items.
8. **Empty list items** (`src/editor/listItemRoundTrip.ts`): an empty bullet/ordered item is written as a bare marker (`*` / `1.`), never `* <br />` — `<br />` opens a CommonMark HTML block that swallows the item's nested children on reload. Parsing gives an item whose nested list starts on a later line (`* ` + children, Obsidian's empty parent) an empty leading paragraph; `* 1) text` on one line stays a list-first item. Before parsing, `normalizeEmptyItems()` rewrites legacy `* <br />` lines to bare markers and an empty task `* [ ] ` / `* [x]` to `* [ ] <br />` (remark alone reads `[ ]` as text and would write `* \[ ]`); on save `stripEmptyTaskBreaks()` writes it back as `* [ ]` — `<br />` never reaches the disk. **Mixed markers** (GRO-2112): the same pass runs `unifySiblingMarkers()` — `-`, `*` and `+` are one bullet: bullets at one indent parse as ONE list (the first sibling's marker wins on load; a blank line starts a new list, as in Obsidian). CommonMark would otherwise start a new list on every marker change. Line rules live in the function's docblock. Disk is untouched by loading; the first save writes `*` throughout (rule 6) as before.

9. **Depth bullet glyphs** (GRO-2013, `src/editor/outline/bullets.css`): CSS only — Crepe's bullet svg is hidden and `.label.bullet::after` draws ● / ○ / ■ by nesting depth of `.milkdown-list-item-block` (repeating every three levels; ordered levels count), `--list-indent: 2.15em`, marker colour 78% of the text colour, all from Crepe theme tokens. Heading-first items (`* # Part 1`) offset the label row by the heading's margin and size it to the heading's line box (`--list-label-offset/height`, shared with the fold chevron). Markdown untouched.
10. **Typography** (GRO-2009, `src/app.css`): Obsidian defaults — system font stack, 16px / 1.5 body, heading scale 1.802 / 1.602 / 1.424 / 1.266 / 1.125 / 1em at weight 600 (h1 700), line-height 1.3 — set through Crepe's `--crepe-font-*` / `--crepe-base-font-size` custom properties on `.editor-instance .milkdown`.

11. **Underline** (GRO-2028, `src/editor/marks/underline.ts`): ProseMirror mark `underline` (`<u>` in the DOM). On disk it is obsidian-underline's inline HTML `<u>text</u>`: a `$remark` plugin wraps each mdast `html("<u>")` … `html("</u>")` pair (nearest match, any depth, inside any inline parent such as `**…**`) into an `underline` mdast node after parsing, and registers the remark-stringify handler that writes it back as `<u>` + children + `</u>` — so `a <u>b</u> c` round-trips byte-identically. Unmatched tags and every other inline HTML keep going through Milkdown's `html` atom node unchanged. Not a Crepe feature (allowlist untouched, no toolbar button).

12. **Zoom into a bullet** (GRO-2029, `src/editor/outline/zoom.ts` + `zoom.css`): view state ONLY, like folding — the plugin holds the zoomed `list_item` position (mapped through every transaction; cleared if the item is deleted), and decorations hide every block off the path root → zoomed item (`outline-zoom-hidden`), strip the ancestors' glyph/chevron/first block (`outline-zoom-ancestor`, a folded ancestor renders expanded without touching fold state) and render a breadcrumb widget (`File name › Ancestor › … › Item`, labels = first-block text truncated at 40 chars; crumbs zoom to that ancestor, the file crumb zooms out fully). Triggers: click the bullet glyph (`.label-wrapper`; task checkboxes keep toggling), `Mod-.`, `Mod-Shift-.` (see Keyboard). Zooming dispatches a metadata-only transaction: never `markdownUpdated`, disk untouched, fold state unaffected. Not persisted — switching files remounts the editor and clears it, and an external file change (watcher → `replaceAll`) replaces the doc and clears it too. `createCrepe({ zoom: { fileName } })`; allowlist untouched. **History** (GRO-2091): every zoom change (glyph, crumb, `Mod-.`, `Mod-Shift-.`, zoom-out included) pushes one in-memory entry `history.state = { mdappZoom: { file, key } }` with the URL untouched (2-arg `pushState`; `key` = fold-key scheme over ALL list items, `null` = zoomed out), and `popstate` restores that level without pushing — so Back / Forward walk zoom levels. Entries of another file are ignored (left behind by a file switch → a Back press can be silent), an unresolvable key zooms out, the original page entry (no zoom state) = zoomed out.

13. **List guide lines** (GRO-2030, `src/editor/outline/guideLines.ts` + `.css`): every nested list (`li.list-item > .children > .content-dom > ul/ol`) gets a CSS `::before` strip — 10px wide, absolutely positioned (`-1 * (--list-indent / 2 + 10px)`) so its centred 1px line runs under the parent's glyph centre; zero layout shift, folded lists take their line with them, colours from `currentColor` (14%, hover 35%). Pseudo boxes hit-test as the list element, so a pointer left of the list's border box = the strip: the plugin's `handleDOMEvents` turns mousedown into `toggleOutlineFoldChildren(listPos)` (GRO-2107: folds / unfolds every parent item directly inside that list — the bullets alongside the line, never the line's owner; an all-leaf line is a swallowed no-op; mixed-marker siblings (GRO-2031) render as two lists with two lines and each line acts on its own list — markdown/mtime untouched, caret unmoved) and mousemove into the `outline-guide-hover` highlight (element `:hover` would light up while editing text inside).

### Property index (GRO-2127 contract, GRO-2128 index — now in the Electron main process)

The query engine behind `.base` views reads notes through `IndexRecord`, never the filesystem. Transport: bridge method `index(root)` (Desktop D10), no HTTP anywhere — the index (`desktop/src/main/vaultIndex/`) is transport-agnostic (tests call `getIndex` directly); it moved, not rewrote, from the retired server process (GRO-2157).

Files: `shared/types.ts` (`IndexRecord`, `IndexResponse`), `shared/frontmatter.ts` (`splitFrontmatter` — moved from the client, which re-exports it — and `parseFrontmatter`), `desktop/src/main/vaultIndex/scan.ts` (`scanFile` + pure `extractTags` / `extractLinks` / `extractEmbeds`), `desktop/src/main/vaultIndex/registry.ts` (`getIndex`, cache + watcher), `desktop/src/main/vaultIndex/index.ts` (barrel), `client/src/bases/testRecords.ts` (`TEST_RECORDS`).

`IndexResponse { root, records: IndexRecord[], generatedAt }` — `records` is every `.md`/`.markdown` file under `root` (dot-entries and `node_modules` skipped, exactly like `tree(root)`), sorted by path. `.base` files, images and everything else are never records.

| `IndexRecord` field | Value |
|---|---|
| `path` | absolute |
| `name` / `basename` / `ext` | `VSL-v1.md` / `VSL-v1` / `md` (`md` or `markdown`, lower-case, no dot) |
| `folder` | root-relative, `/` separators, `''` at the root (`Content Pillars/1. Agentic Agency`) |
| `size` / `mtime` / `ctime` | bytes / mtime ms / birthtime ms (ctime ms where the platform has no birthtime) |
| `properties` | frontmatter parsed with yaml's default **core** schema: `null`/booleans/numbers typed, dates stay strings (`date: 2026-08-01` → `'2026-08-01'`), `pillar: null` is present with value `null`. `{}` when there is no frontmatter, the block is not a map, or YAML fails — the latter two also set `frontmatterError` (one-line yaml message or `frontmatter is not a map`). Files over `MAX_FILE_BYTES` are stat-only (`{}`, empty lists, no error). |
| `tags` | frontmatter `tags`/`tag` (list → each string item; string → split on commas/whitespace; non-strings ignored; leading `#` stripped) followed by inline `#tags` in order of appearance. Inline rule: `#` preceded by start of text, whitespace or one of `( [ , ;`, then `[A-Za-z0-9_/-]+` with at least one non-digit (`#123` is not a tag), case preserved, nested `a/b` kept whole. Never inside fenced code (``` or ~~~), inline code spans or `http(s)://…` runs. De-duplicated, first appearance wins. |
| `links` | `[[target]]` targets with `\|alias`, `#heading` and `#^block` stripped and trimmed — frontmatter string values (top-level and inside lists) that are exactly `[[…]]` first, then the body. Embeds are excluded. De-duplicated. |
| `embeds` | `![[target]]` targets from the body, same stripping, de-duplicated. |

Tags, links and embeds share one code-stripping pre-pass (`stripCode` in `scan.ts`): nothing inside a fenced code block (``` or ~~~) or an inline code span counts, matching Obsidian's metadata cache; `http(s)://…` runs are additionally ignored for tags only. Frontmatter values are never code-stripped.

`TEST_RECORDS` (`client/src/bases/testRecords.ts`) is the 8-note `bases-fixture` as records rooted at `/vault` with `size`/`ctime`/`mtime` zeroed; `desktop/src/main/vaultIndex/registry.test.ts` deep-equals the live scan to it, so client query tests and the main-process index are pinned to one truth.

Cache lifecycle (`getIndex(root)`):
1. First call: walk the root (`isSkipped` pruning, markdown only, 32 reads in flight), `scanFile` each file, keep a `Map<path, IndexRecord>`; concurrent first calls for one root share the single scan. A missing / non-directory root rejects with the same `BridgeFailure` codes as the fs bridge (`NOT_FOUND`, `NOT_A_DIRECTORY`, `FORBIDDEN`).
2. The root's shared chokidar watcher (`watchers.subscribe`) keeps the map live: `add`/`change` on a markdown path → re-`scanFile` and replace (a file that vanishes before the scan is dropped), `unlink` → delete, `unlinkDir` → delete every record under it; `addDir`/`ready`/`error` are no-ops. No rescan is ever needed.
3. Every call returns the map sorted by path with a fresh `generatedAt` and resets a 10-minute idle timer; on expiry the watcher subscription is released and the map dropped (the next call rescans). Test hooks: `_evictAll()`, `_setIdleMs(ms?)`.

Persistent cache (GRO-2223, decisions D1–D4 — write GRO-2228, load GRO-2229): the record map additionally persists as one JSON per vault in `app.getPath('userData')/index-cache/<first 16 hex of sha256(root)>.json` (`desktop/src/main/vaultIndex/cache.ts` — Electron-free like `store.ts`: `main/index.ts` injects the dir via `initIndexCache`; the vault itself is never written, and cross-machine sync of the cache is a non-goal — the reconcile makes a foreign cache harmless anyway). Payload `{ version: 1, root, records: IndexRecord[] }`; records whose frontmatter carries non-finite numbers (YAML `.inf`/`.nan` — JSON cannot round-trip them) are left out of the write and simply rescan on the next start. Persists are debounced ~5 s per root (`schedulePersist` — called from the watcher-incremental mutations, build success, and idle eviction as a natural last flush point) and land through the same `atomicWrite` as everything else, chained per root so writes never reorder; `flushIndexCache()` writes every pending root at once and joins `store.flush()` in the `before-quit` chain.

THE INVARIANT: the cache is only an accelerator — a wrong, missing, stale or corrupt cache can never produce wrong data. `loadIndexCache(root)` never throws; it answers `{ records, status }` with status `hit`, or degrades: `miss` (no file, or the payload names another root — a hash-prefix collision or a copied cache dir is simply not this vault's cache), `corrupt` (unparsable JSON, wrong shape, or any structurally malformed record — one bad element poisons the whole file), `version-mismatch` (numeric `version` ≠ 1). On build, `reconcile(root, files, load)` (`reconcile.ts`) turns the load into the live map: a non-hit is exactly today's full `scanAll`; on a hit it stat-sweeps every walked-and-cached file and reuses a cached record only when path + mtime + size all match (D2 — the record is its own validation key), `scanFile`-ing anything new or differing and dropping per-file stat/scan errors silently (same semantics as `scanAll`). The sweep is a sync `statSync` loop (~27 ms at 10k notes) and the cache load happens before `subscribe`, because the fresh watcher's initial scan floods the 4-thread libuv pool right at build time — async stats queue FIFO behind it and drain at the watcher's pace (~10× slower measured); warm 10k start lands ~99 ms vs ~1040 ms cold (GRO-2229 bench).

The reconcile also emits the cold-start diff for E1c rename detection (GRO-2242): `getColdStartDiff(root)` → `ColdStartDiff { root, scannedAt, cacheStatus, added, removed, changed }`, held on the live entry and dropped with it on idle eviction. `added` carries ON-DISK stats and `removed` the CACHED stats — their (size, mtime) join is the rename signal; `changed` lists paths whose mtime or size moved. Miss semantics are honest: on any `cacheStatus` other than `hit` there is no before-snapshot, so all three lists are EMPTY (never "everything added") and `cacheStatus` says why — consumers must check `cacheStatus === 'hit'` before trusting them. Test hooks: `_resetIndexCache()`, `_setPersistDebounceMs(ms?)`.

### Engine (GRO-2132 function library, GRO-2133 filters / sort / group / limit, GRO-2134 summaries)

`client/src/bases/engine.ts` — `runView(def, view, records, { thisFile?, root? }) → ViewResult { rows, groups, summaries, errors, total }`, pure and DOM-free, never throws. Pipeline: filters → values → sort → limit → group → summaries. A record passes when the base-level `def.filters` AND the view's `filters` both pass; `and` / `or` / `not` nest (`not` = none of the children true); a leaf is truthy per `isTruthy` (an ErrorValue fails). Every filter string is compiled once (`compile()` cache); a compile error or a malformed node makes that whole filter reject every row and adds one `EngineError { where, message }` — `where` is `filters` / `views[i].filters`, with `[j]` per child (`views[0].filters[1][0]`). `Row { record, file: FileValue, values }` — `values` is keyed exactly as the view writes the key (`view.order`, else `propertyKeys`): `file.x` is the file field, `formula.x` evaluates the formula (a compile error → ErrorValue cell + one `EngineError` at `formula.x`; an unknown formula is the evaluator's `unknown formula x` ErrorValue with no report), anything else is the note property (`note.` prefix optional) through `fromYaml`. Sort: `view.sort` in priority order, type-aware (numbers, dates/durations by ms, strings `localeCompare` base-insensitive + numeric, booleans false < true, lists by first element, links by target, mixed types by rank), null / missing / ErrorValue always last whatever the direction, path as the final tiebreak. `limit` applies after sort and before grouping; `total` is the pre-limit count. `groupBy` → one `Group { key, label: render(key), rows, summaries }` per distinct key (`equals`, lists by the whole list), ordered by `groupBy.direction` with the same comparator; null / `''` / empty list / ErrorValue rows go to a trailing `{ key: null, label: 'No value' }` group that is always last; no `groupBy` → `groups: null`. `this` is the `FileValue` whose path equals `opts.thisFile`, else null. `propertyKeys(def, view, records)` is `view.order` if set, else `file.name` + every note key seen (sorted, as `note.<key>`); `propertyLabel(def, key)` is `def.properties[key].displayName` (looked up as written, bare and `note.`-prefixed) else the key without `note.`. Budget: 1000 records × 3-clause filter + 2 formulas + sort + groupBy under 50 ms (`engine.test.ts`).

Link resolution (`makeResolver(files, root?)`, also `Scope.resolve`): a target matches by absolute path, then root-relative path (with or without `.md` / a leading slash), then bare basename — duplicate basenames resolve to the SHALLOWEST folder (Obsidian's shortest-path rule, GRO-2190), equal depth to the first in path order; case-insensitive, `[[…]]` / `|alias` / `#heading` stripped. `resolverFor(records, root?)` is the memoized accessor (WeakMap keyed on the records array identity, then per root): `runView` and the editor's wikilink decorations (rule 23) share ONE resolver per index snapshot — a refetched index is a new array and gets a fresh one; the per-resolver target cache is unchanged. It backs the global `file(path)`, `link.asFile()`, and tightens `file.hasLink()`, `link.linksTo()` and link `==` to compare resolved paths — an unresolved side (e.g. `levels.png`, not a note) falls back to the textual `linkTargetsMatch`. Without a resolver `file()` / `asFile()` stay ErrorValues and matching is textual. List helpers `sum() mean() median() min() max()` ignore non-numbers and give null on none.

`client/src/bases/summaries.ts` — `summarize(kind, values, custom?)`: built-ins (`BUILTIN_SUMMARIES`, case-insensitive) `Count` / `Empty` / `Filled` / `Unique` on any type (`isEmpty`, `equals`), `Average` / `Max` / `Median` / `Min` / `Range` / `Stddev` (population) / `Sum` on numbers (non-numbers ignored, none → null), `Earliest` / `Latest` / `Range` (→ duration) on dates, `Checked` / `Unchecked` on booleans; a non-built-in kind is looked up in `custom` (= `def.summaries`) and evaluated with `values` bound to the column (`Scope.extra`), else `ErrorValue('unknown summary kind: …')`. `runView` fills `result.summaries[prop]` over the post-limit rows and `group.summaries[prop]` per group from `view.summaries { prop: kind }`.

### Cell editing (5B — GRO-2141 write path, GRO-2142 editors)

`writeProperty(path, key, value)` (`client/src/bases/writeProperty.ts`) changes ONE frontmatter key of a note on disk: read the current bytes, `setFrontmatterProperty` (`shared/frontmatter.ts`) rewrites just that key, write with `expectedMtime`; on `CONFLICT` it re-reads once and retries — the value the user picked wins over a concurrent edit elsewhere in the file, which is preserved because only this key is rewritten; a second conflict throws (two racing writers means something else is fighting us). Broken frontmatter (`FrontmatterWriteError`) propagates and nothing is written; a no-op edit never touches disk (same rule as the editor's autosave).

Editor inference (`client/src/bases/editorType.ts`, locked precedence): an explicit `.obsidian/types.json` assignment (delivered as `IndexResponse.types`) wins over any inference from values; otherwise the note's own YAML value decides; a note without the key borrows the dominant value type across the view's records; text is the final fallback. `file.*` and `formula.*` never get an editor (read-only). Kinds: text / number / checkbox / date / list / link.

`view/EditableCell.tsx` is one editable property cell, shared by table cells and card/list property rows: the display (typed like a read-only cell) opens the editor on click — or on Enter, via the host view clicking `[data-edit]` — Enter/blur commit through `writeProperty`, Esc cancels; the link editor completes `[[…]]` over the index's basenames through the shared matcher (`links/completion.ts` — one matcher with the editor's `[[` picker, rule 24; GRO-2191). Commits are optimistic: the committed value renders immediately and stays until the index refetch delivers it; a failed write reverts the cell and shows an inline error. Checkboxes are live and commit on every toggle, no edit mode. An untouched chips editor (no chip added/removed, no pending text) never commits — its seed stringifies the list, so a no-op commit would rewrite `[1, 2]` as `['1', '2']` (7B, GRO-2148). The note's own open editor window absorbs the resulting frontmatter-only `change` silently (GRO-2186, see the autosave note under "Bridge API").

### Group drag (5C — GRO-2143)

`view/groupDrag.ts`, shared by the board's columns and the grouped table's sections. `dragKey(view)` is the bare frontmatter key a drop writes — null (drag disabled) unless `groupBy` is a note property; drag is also off in read-only embeds. `useGroupDrag(key, onMove)` owns the transient HTML5 drag state: `source(path, gk)` spreads on each card/row, `target(group)` on each column/section (rows included — events bubble), the hovered target highlights, a drop on the source group is a no-op, and Esc cancels (real drags fire `dragend`; a document keydown fallback covers jsdom). A drop on ANOTHER group fires `onMove(path, value)` with the target's raw YAML value read off that group's FIRST row — so the written type matches what the members already carry — or `undefined` for "No value", which DELETES the key. BaseView owns the optimistic side: `PendingMove { key, value, prevRaw }` per path, patched into the records BEFORE the engine runs (`applyMoves`) so the card lands in its target group with sort/values/summaries consistent, committed through 5B's `writeProperty`. Clearing follows 5B's discipline — an entry clears only when the index refetch moves that key's raw off `prevRaw` (our write landing, or a concurrent writer winning), never before. A failed write drops the move (the card snaps back) and flags the card/row inline (`moveError`). Tests: `view/GroupDrag.test.tsx`.

### New note (5D — GRO-2144)

`newNote.ts`, behind the toolbar's **New** button and each group header's "+" (both absent in read-only embeds). `deriveSeed(def, view)` is pure over the filter ASTs (def + view): equality leaves `note.x == <literal>` seed `x` with the literal's YAML type, `file.hasTag("t")` appends to a `tags` list, and a single `file.inFolder("…")` names the root-relative target folder — only **and-reachable** leaves count (`or`/`not` subtrees are skipped entirely; seeding those would not, or would anti-, satisfy the view), and non-equality rules are ignored by design (locked kickoff decision). A group "+" additionally seeds the group's property with the raw value of that group's first row ("No value" seeds nothing). The note goes to `targetFolder`: the `inFolder` seed under the root, else the base file's folder, else the root; the name is `untitledName` over the basenames already in that folder (`Untitled`, `Untitled 2`, `Untitled 3`…). `createNewNote` creates the file over the bridge, then writes the seed frontmatter as ONE `writeFile` keyed to the created mtime (`seedContent` via `setFrontmatterProperty`; an empty seed writes nothing). Success opens the note; failure shows `.base-view__error` "Could not create note: …" and opens nothing. Tests: `newNote.test.ts`, `view/NewNote.test.tsx`.
