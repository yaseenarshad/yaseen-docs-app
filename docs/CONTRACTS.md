## Bridge API (`window.yaseenDocs`, locked in GRO-2153 — Desktop A1)

The desktop app has no HTTP server (GRO-2095 D2): the renderer is sandboxed and calls the typed bridge the preload installs; `ipcMain.handle` answers from the main process (GRO-2157 deleted the server and every HTTP path). All paths are absolute POSIX paths; no jail — any absolute path is allowed. Every method rejects with a plain `BridgeError { code, message, path?, mtime? }` (`ApiErrorCode` in `shared/types.ts`, plus `CONFLICT` which carries the disk mtime); `client/src/api.ts` wraps it in `ApiRequestError` (same fields) so the renderer can `instanceof` it.

| Bridge | Notes |
|---|---|
| `tree(root)` | `TreeResponse` — recursive; only vault files: `.md`/`.markdown` (`kind: 'markdown'`) and `.base` (`kind: 'base'`, GRO-2123); every dir shows, vault files or not (GRO-2022); dot-entries and `node_modules` skipped; dirs before files, each sorted case-insensitive. Missing / not a dir → `NOT_FOUND` / `NOT_A_DIRECTORY` |
| `readFile(path)` | `FileResponse` — raw UTF-8 content incl. frontmatter; `.md`/`.markdown`/`.base` only (else `UNSUPPORTED_EXTENSION`); `TOO_LARGE` above 10 MiB |
| `writeFile({ path, content, expectedMtime? })` | `FileWriteResponse { path, mtime, size }` — vault files only; atomic write (`<name>.tmp-<rand>` + `rename`); parent dir must exist; if `expectedMtime` is given and the disk mtime differs → rejects `CONFLICT` with the disk `mtime` and nothing is written |
| `createDir(path)` / `createFile(path)` | `CreateDirResponse { path }` / `CreateFileResponse { path, mtime, size }` — parent must exist (else `NOT_FOUND`); `.md`/`.markdown` created empty, `.base` seeded with exactly `views:\n  - type: table\n    name: Table\n` (else `UNSUPPORTED_EXTENSION`); `wx` write, never overwrites: exists → `ALREADY_EXISTS` |
| `pickFolder()` | `PickFolderResponse` — Electron `dialog.showOpenDialog` (`openDirectory` + `createDirectory`) parented to the calling window (`desktop/src/main/ipc/dialog.ts`). Picked → `{ path }` (no trailing `/`); dismissed → `{ cancelled: true }`; dialog failure → `PICKER_FAILED` |
| `watch(root, listener) → unsubscribe` | `WatchEvent`s: first `ready` (at once for late joiners of an already-watched root), then `add` / `change` / `unlink` (+ `mtime`) for vault files and `addDir` / `unlinkDir`; a bad root yields one `error` event and no subscription. One chokidar per root in main shared by every window (`ignoreInitial: true`, `awaitWriteFinish: { stabilityThreshold: 200 }`, ignores dot-entries and `node_modules`); a window going away drops its subscriptions |
| `index(root)` | `IndexResponse { root, records, generatedAt }` (GRO-2129) — every markdown note under `root` as an `IndexRecord` (path/stat fields, frontmatter `properties`, `tags`/`links`/`embeds` incl. body scan — D7), sorted by path; `.base` files are never records. Full scan on first call per root (`desktop/src/main/vaultIndex/`), watcher-incremental after, evicted after ~10 min idle. Client: `useIndex(root, watch)` fetches once per root and refetches (300 ms debounce) on markdown `add`/`change`/`unlink`, `unlinkDir` and `ready` events |
| `state.get/setSettings/setSidebarCollapsed/pushRecent/setFolder/setFolds/onChange` | `AppState` in the main-owned `yaseendocs.json` (GRO-2159, D9; replaces localStorage `mdapp.*`); targeted mutators so windows never clobber each other |
| `window.identity/setIdentity/open/duplicate` | window identity from `?win=<id>` (GRO-2159, see "App state"); `open` (GRO-2160) and `duplicate` = `⌘⇧N` (GRO-2167) reject `IO_ERROR` until then |

Bases (GRO-2097) adds its methods to `YaseenDocsApi` additively (`index(root)` above), never routes.

Notes
- Folder picking (client, `usePickFolder`): "change" / first launch call `pickFolder()`; `{ path }` → set root + push to recents, `{ cancelled }` or a rejection → nothing. One dialog in flight at a time; the trigger button is disabled meanwhile. There is no in-app folder browser.
- Main-process writes trigger `change` events on the watcher; the client must ignore events for a path whose mtime equals the mtime it just received from its own `writeFile` (echo suppression).
- Auto-save: client debounces 500 ms after last `markdownUpdated`, also flushes on file switch / window `beforeunload` (best effort; the close handshake of GRO-2158 is what guarantees the last save). Only content that differs from the last loaded/saved markdown is saved (Crepe's first serialisation is a normalised rewrite and is never written on its own).
- Desktop tests run chokidar with `CHOKIDAR_USEPOLLING=1` (see `desktop/vitest.config.ts`): on macOS libuv starts the FSEvents stream asynchronously, so a write right after `ready` can be missed; polling makes the tests deterministic.

## Editor rules (client)

1. **Frontmatter**: on load, `splitFrontmatter(content)` → `{ frontmatter, body }`; only `body` goes into Crepe. On save, write `frontmatter + getMarkdownForSave(crepe)`. Frontmatter is re-prepended byte-identically (Crepe would otherwise turn `---` YAML into `***` + paragraph + setext heading underline).
2. **Crepe construction**: always via `createCrepe()` — features come ONLY from `src/editor/featureConfig.ts` (`ENABLED_FEATURES` / `DISABLED_FEATURES`, every `CrepeFeature` classified; ImageBlock, TopBar, AI off; `featureConfig.test.ts` asserts the running editor loads exactly the allowlist), list_item content `block+` (extended from GFM task item schema), `markdownUpdated` listener wired.
3. **Save post-processing**: `postProcessMarkdown()` un-escapes `\[\[` → `[[` (wikilinks/embeds).
4. **Replacing content in a live instance** (external change / Reload): `setMarkdown(crepe, md)` → `replaceAll(md, true)` from `@milkdown/kit/utils`, keeping focus and caret. File switch remounts the Crepe host (`key={path}`); the previous file stays on screen until the next one has loaded.
5. **Outline folding** (GRO-2011): `createOutlineFolding()` (`src/editor/outline/`) is registered in `createCrepe()`. Parent `list_item`s (those owning a nested `bullet_list`/`ordered_list`) get a widget `<button class="outline-toggle" aria-expanded>` at the start of their content (one stroked SVG chevron sized by `--fold-chevron-size`, default 14px, rotated −90° via CSS when collapsed — GRO-2093; the 18px box is unchanged so strip/gate geometry holds); collapsing adds `data-outline-folded="true"` to EVERY nested list of the item (CSS `display:none`) — mixed markers at one indent (`* a` then `- b`) are unified on load (rule 8, GRO-2112); should sibling lists still arise (e.g. bullet + ordered), all of them fold (GRO-2031). Toggles are metadata-only transactions (`tr.docChanged === false`) — the listener never fires `markdownUpdated`, `getMarkdownForSave()` is unchanged, and the file's mtime is untouched. Fold keys = FNV-1a hash of the item's first-block text + occurrence index (`outlineFoldKeys.ts`), persisted via `storage.getFolds/setFolds`. Fold transactions carry one of: a position (toggle), `fold-all` / `unfold-all`, `{ set, collapsed }` (GRO-2107 guide-line click: any expanded → collapse all, else expand all), `undo-fold`; the multi-item ones remember the previous collapsed set so ⌘Z reverts them as one step.
6. **Accepted lossy normalisation** (standard remark-stringify behaviour; content preserved, formatting normalised): `-`/`+` bullets → `*` (alternating `-` for adjacent sibling lists), tabs → 2-space indent, `1)` ↔ `1.` ordered markers swap/renumber, setext → ATX headings, two-space hard breaks → `\`, trailing whitespace stripped, `___` → `***`, indented code → fenced, tables re-padded, lazy blockquote continuation gets `> `, `_`/`*`/`[`/`=`/`&` escaped in text where ambiguous, bare URLs/emails → `<autolink>`, file always ends with a single `\n`. First save of an untouched file WILL rewrite the file in this normalised form.
7. **Outliner keymap** (GRO-2012, `src/editor/outline/listCommands.ts`, registered in `createCrepe()` with keymap priority 100): Tab = indent (no-op on a first sibling — never inserts spaces), Shift-Tab = outdent (level 1 → paragraph; following siblings nest under the lifted item), Enter at the end of a parent item = new FIRST child (after the subtree when the parent is folded), Enter on an empty item = outdent / leave the list, Backspace at the start of an item = join into the previous paragraph (empty parent: children take its place; non-empty parent: no-op). Multi-item selection + Tab/Shift-Tab moves all selected items.
8. **Empty list items** (`src/editor/listItemRoundTrip.ts`): an empty bullet/ordered item is written as a bare marker (`*` / `1.`), never `* <br />` — `<br />` opens a CommonMark HTML block that swallows the item's nested children on reload. Parsing gives an item whose nested list starts on a later line (`* ` + children, Obsidian's empty parent) an empty leading paragraph; `* 1) text` on one line stays a list-first item. Before parsing, `normalizeEmptyItems()` rewrites legacy `* <br />` lines to bare markers and an empty task `* [ ] ` / `* [x]` to `* [ ] <br />` (remark alone reads `[ ]` as text and would write `* \[ ]`); on save `stripEmptyTaskBreaks()` writes it back as `* [ ]` — `<br />` never reaches the disk. **Mixed markers** (GRO-2112): the same pass runs `unifySiblingMarkers()` — `-`, `*` and `+` are one bullet: bullets at one indent parse as ONE list (the first sibling's marker wins on load; a blank line starts a new list, as in Obsidian). CommonMark would otherwise start a new list on every marker change. Line rules live in the function's docblock. Disk is untouched by loading; the first save writes `*` throughout (rule 6) as before.

9. **Depth bullet glyphs** (GRO-2013, `src/editor/outline/bullets.css`): CSS only — Crepe's bullet svg is hidden and `.label.bullet::after` draws ● / ○ / ■ by nesting depth of `.milkdown-list-item-block` (repeating every three levels; ordered levels count), `--list-indent: 2.15em`, marker colour 78% of the text colour, all from Crepe theme tokens. Heading-first items (`* # Part 1`) offset the label row by the heading's margin and size it to the heading's line box (`--list-label-offset/height`, shared with the fold chevron). Markdown untouched.
10. **Typography** (GRO-2009, `src/app.css`): Obsidian defaults — system font stack, 16px / 1.5 body, heading scale 1.802 / 1.602 / 1.424 / 1.266 / 1.125 / 1em at weight 600 (h1 700), line-height 1.3 — set through Crepe's `--crepe-font-*` / `--crepe-base-font-size` custom properties on `.editor-instance .milkdown`.

11. **Underline** (GRO-2028, `src/editor/marks/underline.ts`): ProseMirror mark `underline` (`<u>` in the DOM). On disk it is obsidian-underline's inline HTML `<u>text</u>`: a `$remark` plugin wraps each mdast `html("<u>")` … `html("</u>")` pair (nearest match, any depth, inside any inline parent such as `**…**`) into an `underline` mdast node after parsing, and registers the remark-stringify handler that writes it back as `<u>` + children + `</u>` — so `a <u>b</u> c` round-trips byte-identically. Unmatched tags and every other inline HTML keep going through Milkdown's `html` atom node unchanged. Not a Crepe feature (allowlist untouched, no toolbar button).

12. **Zoom into a bullet** (GRO-2029, `src/editor/outline/zoom.ts` + `zoom.css`): view state ONLY, like folding — the plugin holds the zoomed `list_item` position (mapped through every transaction; cleared if the item is deleted), and decorations hide every block off the path root → zoomed item (`outline-zoom-hidden`), strip the ancestors' glyph/chevron/first block (`outline-zoom-ancestor`, a folded ancestor renders expanded without touching fold state) and render a breadcrumb widget (`File name › Ancestor › … › Item`, labels = first-block text truncated at 40 chars; crumbs zoom to that ancestor, the file crumb zooms out fully). Triggers: click the bullet glyph (`.label-wrapper`; task checkboxes keep toggling), `Mod-.`, `Mod-Shift-.` (see Keyboard). Zooming dispatches a metadata-only transaction: never `markdownUpdated`, disk untouched, fold state unaffected. Not persisted — switching files remounts the editor and clears it, and an external file change (watcher → `replaceAll`) replaces the doc and clears it too. `createCrepe({ zoom: { fileName } })`; allowlist untouched. **Browser history** (GRO-2091): every zoom change (glyph, crumb, `Mod-.`, `Mod-Shift-.`, zoom-out included) pushes one in-memory entry `history.state = { mdappZoom: { file, key } }` with the URL untouched (2-arg `pushState`; `key` = fold-key scheme over ALL list items, `null` = zoomed out), and `popstate` restores that level without pushing — so Back / Forward walk zoom levels. Entries of another file are ignored (left behind by a file switch → a Back press can be silent), an unresolvable key zooms out, the original page entry (no zoom state) = zoomed out.

13. **List guide lines** (GRO-2030, `src/editor/outline/guideLines.ts` + `.css`): every nested list (`li.list-item > .children > .content-dom > ul/ol`) gets a CSS `::before` strip — 10px wide, absolutely positioned (`-1 * (--list-indent / 2 + 10px)`) so its centred 1px line runs under the parent's glyph centre; zero layout shift, folded lists take their line with them, colours from `currentColor` (14%, hover 35%). Pseudo boxes hit-test as the list element, so a pointer left of the list's border box = the strip: the plugin's `handleDOMEvents` turns mousedown into `toggleOutlineFoldChildren(listPos)` (GRO-2107: folds / unfolds every parent item directly inside that list — the bullets alongside the line, never the line's owner; an all-leaf line is a swallowed no-op; mixed-marker siblings (GRO-2031) render as two lists with two lines and each line acts on its own list — markdown/mtime untouched, caret unmoved) and mousemove into the `outline-guide-hover` highlight (element `:hover` would light up while editing text inside).

## Keyboard (client)

All bindings are `$shortcut` keymaps registered in `createCrepe()` with priority 100 (Crepe's own keymaps are 50), so they run first and fall through (`return false`) when they do not apply. `Mod` = ⌘ on macOS, Ctrl elsewhere (ProseMirror decides by `navigator.platform`).

| Keys | Where | Does | Source |
|---|---|---|---|
| `Tab` | caret/selection in list items | indent (sink) the item(s); no-op on a first sibling — never inserts spaces | GRO-2012 `listCommands.ts` |
| `Shift-Tab` | list items | outdent (lift); level 1 → paragraph; following siblings nest under the lifted item | GRO-2012 (Crepe default, kept) |
| `Enter` | end of a parent item | new FIRST child (after the folded subtree when the parent is collapsed) | GRO-2012 |
| `Enter` | empty item (no children) | outdent; at level 1 leaves the list as a paragraph | GRO-2012 |
| `Backspace` | start of an item's first block | join into the previous paragraph / parent item; empty parent: children take its place; non-empty parent: no-op | GRO-2012 |
| `Mod-Enter` | list item(s) whose first block touches the selection | cycle bullet → `[ ]` → `[x]` → bullet, each item from its own state; outside lists falls through (table exit / CodeMirror exit keep theirs) | GRO-2027 `hotkeys.ts` |
| `Mod-ArrowUp` / `Mod-ArrowDown` | caret in a list item | fold / unfold that item (`setOutlineFoldAtSelection`, same meta-only transaction as the chevron — persisted, ⌘Z-revertible); leaf or already in that state = consumed no-op; outside lists falls through to the native document-start/end jump | GRO-2092 `hotkeys.ts` |
| `Mod-Shift-u` | anywhere | fold every parent item (`foldAllOutline`, meta-only transaction, persisted via the app state's `folders[root].folds`) | GRO-2027 |
| `Mod-Shift-i` | anywhere | unfold all (`unfoldAllOutline`) | GRO-2027 |
| `Mod-z` | a fold or a zoom was the latest VIEW action (no doc change since) | revert exactly that one step — a fold (single toggle, or the exact pre-fold-all/unfold-all set) or a zoom (back to the previous level; pushes a history entry). Fold and zoom transactions carry `VIEW_ACTION_META` (`viewActions.ts`); each plugin drops its pending undo when the other kind fires, so only the latest is revertible. Otherwise falls through to history's undo. Plugin-appended transactions (e.g. Crepe's trailing paragraph) don't break eligibility | GRO-2075 `outlineFolding.ts`, GRO-2091 `zoom.ts` |
| `Mod-Shift-x` | selection | toggle strikethrough (Obsidian binding; Crepe's `Mod-Alt-x` still works) | GRO-2027 |
| `Mod-u` | selection | toggle underline (`<u>…</u>` on disk) | GRO-2028 `marks/underline.ts` |
| `Mod-.` | caret in a list item | zoom into that item (view-only; breadcrumbs appear); outside lists falls through | GRO-2029 `outline/zoom.ts` |
| `Mod-Shift-.` | while zoomed | zoom out one level (parent item, or fully at top level); not zoomed falls through | GRO-2029 |
| `Shift-Tab` / `Mod-[` | while zoomed, on the zoomed item or a direct child | no-op (lifting would escape the zoomed subtree); everywhere else outdents as usual | GRO-2029 |

14. **Multi-block drag** (GRO-2019, `src/editor/multiBlockDrag.ts`, registered in `createCrepe()`): dragging the block handle while a multi-block selection contains the grabbed block moves the WHOLE selection. A document-capture mousedown expands the selection to whole sibling blocks (`expandedBlockRange`: deepest level containing both ends — sibling `list_item`s inside a nested list, not the outer list) and suppresses Crepe's single-block selection replacement; a capture dragstart hands ProseMirror a fully CLOSED slice (an open slice would splice into the target paragraph) via `dataTransfer` + `view.dragging`; after the drop an `appendTransaction` (on `uiEvent: 'drop'`) deletes the merged empty shell the move-deletion leaves at the origin, walking up wrappers it was the only child of. Drop X-position controls nesting depth (ProseMirror `dropPoint`). A grab OUTSIDE the selection never arms the plugin — Crepe's single-block drag is untouched. Folded parents drag with their hidden children.
15. **Block handle gate** (GRO-2081, `src/editor/blockHandleGate.ts`): while the pointer is inside a guide-line strip band or a fold chevron's box, `.milkdown-block-handle` gets `mdapp-handle-muted` (pointer-events none + invisible) so those clicks land; muting pauses during drags. Band geometry is imported from `guideLines.ts` — one source of truth. Crepe's `blockHandle.shouldShow` config is typed upstream but never consumed; do not reach for it.
16. **Hotkey reference** (GRO-2067, `src/sidebar/HotkeysPanel.tsx`): the keyboard button beside the settings cog lists every binding from the exported `HOTKEYS`/`MOUSE_TIPS` lists — update them together with any keymap change (`HotkeysPanel.test.ts` pins the set).
17. **URL** (GRO-2069, `src/lib/urlHash.ts`): the open file is mirrored as `#/abs/path.md` via `history.replaceState` (never pushState); on boot a hash file wins over the folder's remembered `lastFile` and may live OUTSIDE the current root (the sidebar's stale-file validation skips out-of-root paths). No file → no hash.

18. **Bullet threading** (GRO-2094, `src/editor/outline/bulletThreading.ts` + `.css`): view-only decorations derived from `selection.$from` on every update — `outline-thread-node` on each list_item on the root → caret path (glyph takes the app accent `--accent` via `--list-marker-color` on its `.label-wrapper`; Crepe's frame `--crepe-color-primary` is #333 and would read as black), and inside each NESTED list on the path `outline-thread-seg` on items 0…pathIndex plus `outline-thread-stop` on the path child (segment cut at its glyph centre, elbow into the bullet). Top-level lists have no guide line and get no segments (Logseq-identical). 2px `--accent` `li::before` at the guide-line x with `pointer-events: none` (a pseudo hit-tests as its element; guide-line click-to-fold needs the UL as target). No state, no persistence, never `markdownUpdated`. Drawn only under `.app[data-threading='on']` — the settings-cog "Bullet threading" row (default On, `settings.bulletThreading` in the app state); the cog's "Thread width" (1/2/3px) and "Thread colour" (picker + Default = accent) rows feed `--thread-width` / `--thread-color` (GRO-2109). Caret semantics: the path is that of `selection.$from` — a NodeSelection on an item threads to its parent, a multi-item range threads the first item.

19. **Base files** (GRO-2125, `src/bases/BaseHost.tsx`): `Editor` switches on `fileKind(file.path)` — `'base'` mounts `BaseHost`, everything else `CrepeHost`; both are keyed by path and share `useAutosave` / `SaveIndicator` / the conflict bar, so the autosave, echo-suppression and 409 rules above apply unchanged. Frontmatter is ALWAYS `''` for a base (the whole file is the YAML document; nothing is split off or re-prepended). On mount `parseBase(content)` → **view mode** (`BaseView`: the 4A view chrome, see "View chrome (GRO-2135)"; the table body lands in 4B) or, on `BaseParseError` (YAML error or missing/ill-typed `views`), **raw mode**: the error line (`.base-error`, `line:col` prefixed when the parser located it) above a `<textarea class="base-raw">` holding the file byte-for-byte; every keystroke is re-parsed and the first valid text flips back to view mode (same autosave controller, only its content source changes). Disk content is whatever the current mode yields: `serializeBase(parsed)` in view mode, the textarea text in raw mode. External `change` events reload into whichever mode the fresh content parses to, or show the conflict bar when dirty. Invariant: **opening a base and doing nothing never writes** — the autosave baseline is the first serialisation and only content that differs from it is saved (`BaseHost.test.tsx` pins this for both modes). 1B normalisation note: `yaml`'s `indentSeq` is document-global, so a hand-written file mixing sequence-indent styles (`- ` flush with its key in one place, indented in another) is re-indented to one style on its first REAL save; Obsidian-written files round-trip byte-identically (comments, blank lines, flow/block style and unknown keys included).

## App state (`yaseendocs.json`, main-owned — GRO-2159, D9)

One user-global JSON file owned by the main process: `app.getPath('userData')/yaseendocs.json` = `~/Library/Application Support/Yaseen Docs/yaseendocs.json` (`app.setName('Yaseen Docs')` runs before anything reads userData; `--user-data-dir=<dir>` relocates it, which is how the Playwright checks seed state). `localStorage` is not used at all. The renderer never touches the file: it reads a cache (`client/src/lib/storage.ts`, filled by `storage.init()` before the first render) and writes through the targeted `state.*` mutators; `desktop/src/main/store.ts` owns the file. Nothing here is ever written into the vault or the markdown.

| Key | Shape | Rules |
|---|---|---|
| `version` | `1` | anything else → the file is treated as corrupt (see below) |
| `settings` | `SettingsState` `{ lineSpacing, blockGap, bulletThreading, threadWidth, threadColor }` | global: one value for every folder and window; validated field by field on load (`threadWidth` ∈ 1/2/3, `threadColor` `#rrggbb` or null), an invalid field falls back to `DEFAULT_SETTINGS`; `setSettings` takes a complete valid object (else `BAD_REQUEST`) |
| `sidebarCollapsed` | `boolean` | global; non-boolean → `false` |
| `recents` | `RecentRoots` `[{ path, lastOpened }]` | most-recent first, de-duplicated by path, max 10 (`pushRecent(path)`, absolute path); wrong shape → `[]` |
| `windows` | `WindowEntry[]` `{ id, root, file, bounds: { x, y, width, height } }` | one entry per open window, reopened on relaunch (bounds applied as stored; clamping/restore polish is GRO-2160); malformed or duplicate-id entries dropped on load; `upsertWindow` replaces by id or appends; an entry is removed when its window closes — unless the app is quitting (⌘Q, or the last window closing, which quits), so relaunch restores the same windows |
| `folders[root]` | `FolderState` `{ expanded: string[], lastFile: string \| null, folds: { [file]: string[] } }` | per folder; `setFolder(root, { expanded?, lastFile? })` merges and creates the entry with defaults when missing (other keys ignored); `setFolds(root, file, keys)` replaces one file's collapsed outline fold keys (max 500; an empty list removes the file entry, the folder entry stays); invalid fold lists dropped on load |

Write semantics: every mutation updates memory, notifies `onChange` listeners synchronously and schedules one debounced (150 ms) atomic write (`<file>.tmp-<rand>` + rename, pretty-printed JSON, parent dir created on demand); `flush()` writes at once and `will-quit` holds the quit until it lands (`event.preventDefault()` + `app.exit(0)`), so nothing is lost on ⌘Q. A file that is unparsable, not an object or not `version: 1` is moved to `yaseendocs.json.corrupt-<epoch>` and the defaults are used — the bad file is never overwritten silently. Unknown top-level keys are dropped on load.

Live broadcast: after any change — from any window, or from main itself (window upserts) — every live `BrowserWindow` gets `state:changed` with the whole new state; the preload surfaces it as `state.onChange`, the client cache replaces itself and `storage.subscribe` listeners fire (`App` re-reads settings and `sidebarCollapsed`). A window's own writes update its cache optimistically and do not fire its subscribers until the echo arrives.

Per-window identity: main loads each window as `<renderer>?win=<id>` and keeps a `webContents.id → window id` registry (`desktop/src/main/windows.ts`). `window.identity()` answers `{ id, root, file }` from `windows[]` for the calling window (`BAD_REQUEST` for an unregistered sender, `NOT_FOUND` once the entry is gone); `window.setIdentity({ root?, file? })` merges into that entry (absolute paths or null; `id` and `bounds` cannot be changed this way). On the client, `storage.getRoot()` IS the identity's root; `setRoot` also clears `file` when the root changes; `setLastFile(root, file)` records both the folder's `lastFile` (for the next time that folder opens) and the window's `file` (what is open now). `window.open` / `window.duplicate` reject `IO_ERROR` until GRO-2160 / GRO-2167.

## Bases modules

### Property index (GRO-2127 contract, GRO-2128 server index)

The query engine behind `.base` views reads notes through `IndexRecord`, never the filesystem. Transport: bridge method `index(root)` (Desktop D10), **no HTTP route** — `server/src/vaultIndex/` is transport-agnostic (no `hono`, no `electron` import; tests call `getIndex` directly) so it moves, not rewrites, into the Electron main process.

Files: `shared/types.ts` (`IndexRecord`, `IndexResponse`), `shared/frontmatter.ts` (`splitFrontmatter` — moved from the client, which re-exports it — and `parseFrontmatter`), `server/src/vaultIndex/scan.ts` (`scanFile` + pure `extractTags` / `extractLinks` / `extractEmbeds`), `server/src/vaultIndex/registry.ts` (`getIndex`, cache + watcher), `server/src/vaultIndex/index.ts` (barrel), `client/src/bases/testRecords.ts` (`TEST_RECORDS`).

`IndexResponse { root, records: IndexRecord[], generatedAt }` — `records` is every `.md`/`.markdown` file under `root` (dot-entries and `node_modules` skipped, exactly like `/api/tree`), sorted by path. `.base` files, images and everything else are never records.

| `IndexRecord` field | Value |
|---|---|
| `path` | absolute |
| `name` / `basename` / `ext` | `VSL-v1.md` / `VSL-v1` / `md` (`md` or `markdown`, lower-case, no dot) |
| `folder` | root-relative, `/` separators, `''` at the root (`Content Pillars/1. Agentic Agency`) |
| `size` / `mtime` / `ctime` | bytes / mtime ms / birthtime ms (ctime ms where the platform has no birthtime) |
| `properties` | frontmatter parsed with yaml's default **core** schema: `null`/booleans/numbers typed, dates stay strings (`date: 2026-08-01` → `'2026-08-01'`), `pillar: null` is present with value `null`. `{}` when there is no frontmatter, the block is not a map, or YAML fails — the latter two also set `frontmatterError` (one-line yaml message or `frontmatter is not a map`). Files over `MAX_FILE_BYTES` are stat-only (`{}`, empty lists, no error). |
| `tags` | frontmatter `tags`/`tag` (list → each string item; string → split on commas/whitespace; non-strings ignored; leading `#` stripped) followed by inline `#tags` in order of appearance. Inline rule: `#` preceded by start of text, whitespace or one of `( [ , ;`, then `[A-Za-z0-9_/-]+` with at least one non-digit (`#123` is not a tag), case preserved, nested `a/b` kept whole. Never inside fenced code (``` or ~~~), inline code spans or `http(s)://…` runs. De-duplicated, first appearance wins. |
| `links` | `[[target]]` targets with `\|alias`, `#heading` and `#^block` stripped and trimmed — frontmatter string values (top-level and inside lists) that are exactly `[[…]]` first, then the body. Embeds are excluded. De-duplicated. |
| `embeds` | `![[target]]` targets from the body, same stripping, de-duplicated. |

Tags, links and embeds share one code-stripping pre-pass (`stripCode` in `scan.ts`): nothing inside a fenced code block (``` or ~~~) or an inline code span counts, matching Obsidian's metadata cache; `http(s)://…` runs are additionally ignored for tags only. Frontmatter values are never code-stripped.

`TEST_RECORDS` (`client/src/bases/testRecords.ts`) is the 8-note `bases-fixture` as records rooted at `/vault` with `size`/`ctime`/`mtime` zeroed; `server/src/vaultIndex/registry.test.ts` deep-equals the live scan to it, so client query tests and the server index are pinned to one truth.

Cache lifecycle (`getIndex(root)`):
1. First call: walk the root (`isSkipped` pruning, markdown only, 32 reads in flight), `scanFile` each file, keep a `Map<path, IndexRecord>`; concurrent first calls for one root share the single scan. A missing / non-directory root rejects with the same `ApiFailure` codes as the HTTP routes (`NOT_FOUND`, `NOT_A_DIRECTORY`, `FORBIDDEN`).
2. The root's shared chokidar watcher (`watchers.subscribe`) keeps the map live: `add`/`change` on a markdown path → re-`scanFile` and replace (a file that vanishes before the scan is dropped), `unlink` → delete, `unlinkDir` → delete every record under it; `addDir`/`ready`/`error` are no-ops. No rescan is ever needed.
3. Every call returns the map sorted by path with a fresh `generatedAt` and resets a 10-minute idle timer; on expiry the watcher subscription is released and the map dropped (the next call rescans). Test hooks: `_evictAll()`, `_setIdleMs(ms?)`.

### Engine (GRO-2132 function library, GRO-2133 filters / sort / group / limit, GRO-2134 summaries)

`client/src/bases/engine.ts` — `runView(def, view, records, { thisFile?, root? }) → ViewResult { rows, groups, summaries, errors, total }`, pure and DOM-free, never throws. Pipeline: filters → values → sort → limit → group → summaries. A record passes when the base-level `def.filters` AND the view's `filters` both pass; `and` / `or` / `not` nest (`not` = none of the children true); a leaf is truthy per `isTruthy` (an ErrorValue fails). Every filter string is compiled once (`compile()` cache); a compile error or a malformed node makes that whole filter reject every row and adds one `EngineError { where, message }` — `where` is `filters` / `views[i].filters`, with `[j]` per child (`views[0].filters[1][0]`). `Row { record, file: FileValue, values }` — `values` is keyed exactly as the view writes the key (`view.order`, else `propertyKeys`): `file.x` is the file field, `formula.x` evaluates the formula (a compile error → ErrorValue cell + one `EngineError` at `formula.x`; an unknown formula is the evaluator's `unknown formula x` ErrorValue with no report), anything else is the note property (`note.` prefix optional) through `fromYaml`. Sort: `view.sort` in priority order, type-aware (numbers, dates/durations by ms, strings `localeCompare` base-insensitive + numeric, booleans false < true, lists by first element, links by target, mixed types by rank), null / missing / ErrorValue always last whatever the direction, path as the final tiebreak. `limit` applies after sort and before grouping; `total` is the pre-limit count. `groupBy` → one `Group { key, label: render(key), rows, summaries }` per distinct key (`equals`, lists by the whole list), ordered by `groupBy.direction` with the same comparator; null / `''` / empty list / ErrorValue rows go to a trailing `{ key: null, label: 'No value' }` group that is always last; no `groupBy` → `groups: null`. `this` is the `FileValue` whose path equals `opts.thisFile`, else null. `propertyKeys(def, view, records)` is `view.order` if set, else `file.name` + every note key seen (sorted, as `note.<key>`); `propertyLabel(def, key)` is `def.properties[key].displayName` (looked up as written, bare and `note.`-prefixed) else the key without `note.`. Budget: 1000 records × 3-clause filter + 2 formulas + sort + groupBy under 50 ms (`engine.test.ts`).

Link resolution (`makeResolver(files, root?)`, also `Scope.resolve`): a target matches by absolute path, then root-relative path (with or without `.md` / a leading slash), then bare basename (first match in path order); case-insensitive, `[[…]]` / `|alias` / `#heading` stripped. It backs the global `file(path)`, `link.asFile()`, and tightens `file.hasLink()`, `link.linksTo()` and link `==` to compare resolved paths — an unresolved side (e.g. `levels.png`, not a note) falls back to the textual `linkTargetsMatch`. Without a resolver `file()` / `asFile()` stay ErrorValues and matching is textual. List helpers `sum() mean() median() min() max()` ignore non-numbers and give null on none.

`client/src/bases/summaries.ts` — `summarize(kind, values, custom?)`: built-ins (`BUILTIN_SUMMARIES`, case-insensitive) `Count` / `Empty` / `Filled` / `Unique` on any type (`isEmpty`, `equals`), `Average` / `Max` / `Median` / `Min` / `Range` / `Stddev` (population) / `Sum` on numbers (non-numbers ignored, none → null), `Earliest` / `Latest` / `Range` (→ duration) on dates, `Checked` / `Unchecked` on booleans; a non-built-in kind is looked up in `custom` (= `def.summaries`) and evaluated with `values` bound to the column (`Scope.extra`), else `ErrorValue('unknown summary kind: …')`. `runView` fills `result.summaries[prop]` over the post-limit rows and `group.summaries[prop]` per group from `view.summaries { prop: kind }`.

### View chrome (GRO-2135)

`client/src/bases/BaseView.tsx` props: `{ parsed, onChange, thisFile, records, indexStatus: 'pending' | 'ready', onOpenFile }`. **Write-through**: every config change is `onChange(updateBase(parsed, mutate))` (re-parsed via `parseBase(serializeBase(…))` so sequential edits inside collections a previous edit created keep working — `doc.setIn` stores plain JS values), exactly one `onChange` per interaction, no Save button; BaseHost turns it into the normal autosave. `onOpenFile` is threaded App (`openFile`) → `Editor` → `BaseHost` → `BaseView`; BaseHost passes `records=[]` + `indexStatus="pending"` until 2C wires `useIndex`. Only the active tab and the search text are component state — everything else lives in the file. The body switches on `view.type`: `table` → `TableView`, `board` (OUR schema extension, D1 — Obsidian ignores it and the keys round-trip untouched) → `BoardView`, anything else → the 4A placeholder row list.

Toolbar (`view/Toolbar.tsx`, `.base-toolbar`): left `view/ViewTabs.tsx` — one `role="tab"` per view (type glyph + name, active tab accent underline), "+" appends `{ type: 'table', name: 'Table N' }` (N = views.length + 1) and activates it; the active tab's "…" (or right-click on any tab) opens the view menu: Rename (inline input), Duplicate (`<name> copy`, inserted after, config cloned), Delete (disabled for the only view; selects the neighbour), Move left / Move right (selection follows). Right: **Filter** (badge = `countRules(def.filters) + countRules(view.filters)`; a second red badge + messages in the popover when `result.errors` is non-empty), **Sort** (badge = sort count + 1 for an active `groupBy`), **Properties**, **Search** (inline input; filters the shown rows client-side over every rendered value, case-insensitive; no write), and the count — `N items`, or `shown / total items` when search or `limit` reduce it. Popovers (`view/Popover.tsx`, `.base-popover`) anchor under their trigger, close on Esc / click-away, move focus in on open. `view/TextField.tsx` commits on Enter/blur only (one change per edit), Esc reverts.

Filter menu (`view/FilterMenu.tsx`): conjunction **All / Any / None** → `and` / `or` / `not` (always written in the explicit map form; the last removed rule deletes the `filters` key); scope **This view / All views** selects which node the menu edits (`view.filters` vs `def.filters` — a display selection, not a move; both sets stay in the file). Rule rows are property · operator · value; a new rule is `file.name contains ""` so nothing blanks while it is filled in. **Advanced** shows each string rule's raw expression in a text input; strings the builder cannot parse and nested groups render as read-only code rows (removable; strings still editable under Advanced). The rule ↔ expression mapping is the pure `view/filterRows.ts`: `ruleToExpr(rule)` / `exprToRule(expr) → Rule | null` (round-trip pinned for every operator in `filterRows.test.ts`), `inferType(property, records)` (first non-empty value; `fromYaml` typing; a list is `tags` only for the `tags` property; `file.size` number, `file.ctime`/`file.mtime` date, formulas/unknowns text), operators per type — text is/is not/contains/does not contain/starts with/ends with/is empty/is not empty; number `== != < > <= >=`/empty; date is/is before/is after (`date("…")` literals)/empty; checkbox `== true` / `== false`; list & tags contains/does not contain/empty; and the file pseudo-properties `file.tags` / `file.folder` / `file.links` → `file.hasTag("t")` / `file.inFolder("f")` / `file.hasLink("l")`. Property keys are canonical (`note.x` / `file.x` / `formula.x`; non-identifier names as `note["…"]`).

Sort menu (`view/SortMenu.tsx`): `view.sort` rows (property select, ASC/DESC toggle, up/down, remove — an empty list deletes the key) + "Add sort" (`file.name ASC`); beneath, **Group by** writes `view.groupBy { property, direction }` ("None" deletes it) — rendering of groups is 4C. Properties menu (`view/PropertiesMenu.tsx`): checklist over the shown keys (as written, so `view.order` round-trips) plus every other known key (`view/properties.ts` `allPropertyKeys`: shown + `file.name` + note keys + formulas, deduped canonically); toggling/reordering writes `view.order` (shown keys only, in order; `file.name` cannot be hidden — it is the row link); the pencil sets `def.properties[key].displayName` (looked up as written / bare / `note.`-prefixed, written bare for note keys; empty deletes the displayName and an emptied entry/map).

Body (4A placeholder, view types with no real body yet): one row per result — `file.name` as a button calling `onOpenFile(record.path)`, then the other `order` values `render()`ed and ` · `-joined. `indexStatus === 'pending'` replaces the rows with `.base-view__pending` "Waiting for the vault index (desktop bridge pending)". Tests: `view/filterRows.test.ts`, `view/Toolbar.test.tsx` (mounts BaseView over `TEST_RECORDS` + Yasin's base; asserts YAML via `serializeBase` next to the DOM), and `BaseHost.test.tsx` (a toolbar change → one PUT after the debounce).

Table (4B, GRO-2136, `view/TableView.tsx`, `.base-table`): `type: table` renders a `<table>` over the post-search rows — sticky header (labels via `propertyLabel`), columns = `propertyKeys` in `order`, widths from `view.columnSize` (px per key, default 150; drag the header's right-edge handle, min 60, live preview, ONE write on mouseup), `view.rowHeight` presets short/medium/tall → 28/44/68px via `--base-table-row-h`. The `file.name` cell is a `.base-table__link` button → `onOpenFile`; other cells by type — numbers right-aligned (`.base-table__cell--num`), booleans read-only checkboxes (editing is 5B), lists and links/files as chips (`.base-table__chip`, `--link`), ErrorValues as a red `#ERROR` chip with the message in `title`, everything else `render()`. Summary row pinned in `<tfoot>`: each cell is a click-to-pick kind (None + `BUILTIN_SUMMARIES` + `def.summaries` names) writing `view.summaries[columnKey]` (existing keys matched canonically; removing the last kind deletes the map), value shown via `summarize` over the shown rows. Arrow keys move focus between body cells (`data-cell="row:col"`), Enter on a name cell opens the note. Above 500 rows only a scroll-positioned slice of `<tr>`s is mounted between spacer rows (no library); rows render from one flat slice so 4C can interleave group header rows. Tests: `view/TableView.test.tsx`.

Board (4D, GRO-2138, `view/BoardView.tsx`, `.base-board`): `type: board` is OUR schema extension (D1) — the view keys are `type: board`, `groupBy` (required for columns), `order` (the card fields) and `cardSize: small | medium | large` (column width 220/280/340px via `--base-board-col-w`, default medium; anything else = medium); Obsidian ignores the view and every key round-trips byte-for-byte (`baseFile.test.ts` board fixture). Columns = the engine's post-search groups on one horizontally scrolling row (a column with no shown cards disappears, "No value" last); each column header is the shared `GroupHeader` content (chevron, typed value, count, per-column summaries over the SHOWN cards). Cards: `file.name` as a `.base-board__title` button → `onOpenFile`, then the view's other `order` properties as small label/value rows (`propertyLabel` + the table's typed `cellContent` — shared from `GroupHeader.tsx`; a missing value keeps the label with an empty value). Collapsing a column hides its cards and keeps the header — the SAME persisted state as the table's groups (`baseGroups[<basePath>::<viewName>]`, never the `.base` file). Without `groupBy` the body is a centered `.base-board__hint` whose "Group by…" button writes the first non-file property as `view.groupBy { property, direction: ASC }` through the file (one write; the Sort menu edits it after). Out of scope until later units: card images (4E), drag between columns (5C). Tests: `view/BoardView.test.tsx`.
