# Yaseen Docs: every feature

The full reference. For the short tour with pictures, see the [README](../README.md).

Yaseen Docs — a local markdown editor for a folder of notes (e.g. an Obsidian vault), as an Electron desktop app for macOS and Windows: a React renderer running [Milkdown Crepe](https://milkdown.dev/), and a main process that reads and writes the files on this machine (the renderer only ever talks to the `window.yaseenDocs` bridge — there is no server of any kind). Pick a folder, browse its `.md` files in the sidebar, edit WYSIWYG, and changes are saved back to disk (debounced, atomic). Excalidraw drawings (`.excalidraw`) and draw.io diagrams (`.drawio`) open in tabs too (see [Drawings and diagrams](#drawings-and-diagrams)). Files changed outside the app (another editor, sync) are reloaded live; if you have unsaved edits you get a Reload / Keep mine choice. YAML frontmatter is preserved byte-for-byte. Lineage in one line: product behaviour follows Obsidian, the transport mechanism follows VS Code (sandboxed renderer + typed preload bridge + main-process fs).

## Requirements

Node.js 20.19 or newer (22+ recommended), npm, macOS or Windows (the packaged apps target macOS arm64 and Windows x64; the dev build runs wherever Electron does).

## Run

```sh
npm install
npm run dev      # launches the Electron app with HMR
```

See `docs/DEVELOPMENT.md` for the full launch recipe (state file, packaged-app install, agent verification).

```sh
npm test         # unit tests (vitest, four projects: client jsdom, desktop node, tools node, perf jsdom)
npm run typecheck
npm run build    # electron-vite build into desktop/out
npm run e2e      # 60 Playwright-Electron specs driving the real app
```

## Build the app

```sh
npm run desktop:build
```

produces `desktop/dist-app/mac-arm64/Yaseen Docs.app` and `desktop/dist-app/Yaseen Docs-<version>-arm64.dmg` (arm64, ad-hoc signed). Drag the `.app` into `/Applications`, or send someone the dmg.

## Sharing it

Every packaged version is downloadable from the repo's [Releases page](https://github.com/yaseenarshad/yaseen-docs-app/releases) — the `.dmg` for a Mac (Apple Silicon), the `-win-x64-setup.exe` for Windows — no build toolchain needed on the installing machine.

The Mac app is signed with a free self-signed certificate, not notarized, so on someone else's Mac (macOS 15) the first open is blocked with "Apple could not verify…". Once: open **System Settings › Privacy & Security**, scroll to the blocked-app notice, click **Open Anyway**, and confirm. After that it opens normally. Every version carries the same signature, so macOS keeps the permissions you gave it when the app updates (YAZ-2976 D1). The Windows installer is unsigned, so SmartScreen shows "Windows protected your PC" the first time: click **More info › Run anyway**, once.

### Updates

The app updates itself from the repo's [Releases page](https://github.com/yaseenarshad/yaseen-docs-app/releases) (YAZ-2976). It checks 10 seconds after launch, then every 12 hours; **Yaseen Docs › Check for Updates…** checks at once and answers in the window in front, with or without a sidebar: it says so when you already have the newest version, says when a download is under way, and opens **What's new** when an update is ready or available. On a Mac it downloads the new `.dmg` in the background, checks the sha256 that GitHub publishes for it, and checks that the app inside carries the same signature as the running app — a build signed by anyone else is refused and is offered as **🎉 New update ready** from then on, so you can install it by hand. A version that the app could not swap in is offered the same way. Then a small **🎉 New update ready** pill shows beside the settings cog. It opens **What's new**, which fills most of the window (YAZ-2988). An ✕ at the top right, Esc, a click outside or **Later** closes it. The left column lists every release, newest first, under one heading per year; each row is the version with a short date ("Oct 17"), and under it a one-line short title: the first feature of the release and how many more ("Tab Names +2 more"): **Latest** marks the newest one, **Your current version** marks yours (both on one row when you are up to date), and a thin line above and below your row shows where you are; every row above it is newer. Click a row, or use ↑ and ↓, to read its notes on the right, with their GIFs and pictures. With an update waiting it opens on the latest release, otherwise on yours. If you are not on the latest version, select the **Latest** row: **Update to v…** checks for it at once (YAZ-4371). The button then says **Downloading v…** while the new version downloads in the background, then **Restart to update**; a copy that cannot replace itself gets **Download**, which opens the release page. If the check cannot reach GitHub, one line says so and the button stays, so you can try again; if the new version's download is not published yet, a line says to try again in a few minutes; if the download fails after the click, a line says so and the button stays, so you can try again (YAZ-4384). Other rows, an up-to-date app and a development run with no update feed show no such button; **Restart to update** and **Download** work from every row. Click a picture or a GIF to see it big; ← and → go to the other pictures of that release, and Esc closes the picture first, then the window. **Restart to update** saves every window, quits, swaps the app in place and opens it again; if you click **Later**, the next normal quit installs it. The first launch of the new version shows no pill: you read the notes before you restarted. **Help › What's New…** opens the same window at any time.

A copy that cannot replace itself — Windows, a copy run from the `.dmg` or not yet moved to Applications, a folder you cannot write, or a local build of this version or later that has no certificate (an ad-hoc signature) — shows **🎉 New update ready** instead, and its button opens the Releases page. Versions 1.0.12 and older have no updater: install the first signed version by hand once, and the updates after it install themselves.

GitHub sync uses the computer's own git, found at a fixed set of locations rather than on `PATH` (`desktop/src/main/git/exec.ts`): on a Mac the Command Line Tools or Homebrew git, on Windows [Git for Windows](https://git-scm.com/download/win) (its installer bundles the Git Credential Manager, so a one-time GitHub sign-in sticks). Without one, the sync banner says so and offers a setup prompt to paste into an LLM.

## Editing

Lists behave like an outliner (Obsidian / Logseq), see `docs/CONTRACTS.md` "Editor rules" and "Keyboard" for the exact semantics:

- **Fold**: parent bullets get a chevron — and so do `H1`–`H3` headings outside lists, where the chevron collapses the heading's section (everything up to the next same-or-bigger heading). A bullet holding an image folds too: the picture shrinks to a small thumbnail on the line (type before or after it to name it), clicking the thumbnail unfolds it, and an expanded image shows a corner button that folds it back. Collapsed state is remembered per file in the app state file (`~/Library/Application Support/Yaseen Docs/yaseendocs.json`) only — the markdown on disk (and its mtime) is never touched by folding. `⌘↑` / `⌘↓` fold / unfold the bullet or heading section at the caret (Logseq's defaults; a no-op on leaves, native document jump outside both), `⌘⇧U` folds every foldable bullet, `⌘⇧I` unfolds all, and `⌘Z` right after a fold reverts it (folds older than the latest action stay put; `⌘Z` is normal text undo otherwise). **Lock open**: right-click a bullet's dot or a heading's chevron › **Lock open**, and that row and the rows inside it never fold; its chevron shows a lock. A row above it still folds. **Unlock** in the same menu takes it away; a lock is remembered per note, as folds are.
- **Collapse all / Expand all**: the double chevron at the top right of a note, left of the page cog, folds everything that can fold at once (bullets with children, image bullets and `H1`–`H3` sections); once everything is folded, the same button opens them all. Point at it to see what it will do and its key (⌘⇧U / ⌘⇧I); a note with nothing to fold says "Nothing to fold". The chevrons point up when a click will collapse and down when it will expand. ⌘Z undoes it. It works in a read-only note too. Every fold-all button in the app (the sidebar, folder views, comments, the code outline) works the same way: one button for both, chevrons that show what a click does, and "Nothing to fold" (dimmed, where the button stays) when there is nothing to fold.
- **Bullet threading** (Roam / Logseq "bullet paths"): the lines from each nested list's top down to the bullet at the caret, and the bullets on that path, take the accent colour and stop at the active bullet. While you step through CMD+F's matches, the path goes to the active match instead; a click, a key or an edit in the note gives it back to the caret (YAZ-3166). View-only; Settings › Editor › Bullet threading has **Bullet threading default** (On / Off, default Off), Line width 1/2/3px and Line colour (Default = the app accent). The page cog's **Bullet threading** row turns it on or off for one note, saved in the note (`bullet-threading: true`); that choice wins over the default, the same as Guide lines. In a split view each note shows its own choice.
- **Section indent**: a note that uses headings can read like a bullet note. Turn it on for a note from the page cog ("Section indent", off by default, saved in the note as `section-indent: true`, so it goes with the note to your other Mac): the text stands below its heading, one step in for each level of nesting, and a thin line runs down from each heading to the end of its section. The lines on the way to the caret take the Bullet threading colour and width. A click on a line folds the sections beside it; a second click opens them. View-only, the file never changes; Settings › Editor › Section indent has Step width 24/30/36px and Grey lines (Always show / Only near the mouse).
- **Read only**: the page cog's first row, on every note, drawing and diagram. Turn it on and the app stops your own edits to that file: the text, the title, the properties, the canvas. A **Read only** chip with a lock then shows beside the cog. To edit again, click the chip and then **Allow edits** (`Enter`; `Esc` or **Cancel** keeps it locked). The switch is saved IN the file (`readonly: true` in a note's properties, `"readonly": true` in a drawing's `yaseendraw` block, `yaseendraw-readonly="1"` on a diagram), so it moves with the file and syncs to your other Mac. In a folder's views (table, board, cards, list) the note's cells show their values but do not open, its checkboxes do not change and its card does not move to another column; a tried cell says "This note is read only", and a small grey lock follows the note's name. A read-only note keeps its caret: click to place it, and move with the arrows, ⇧ + arrows to select, ⌘← / ⌘→, ⌥ + arrows, Home / End and the page keys; ⌘↑ / ⌘↓ fold and unfold at the caret, and ⌘A, ⌘C and ⌘F work. In a table the arrows move from cell to cell, and Tab / ⇧Tab go to the next / previous cell. Typing, Enter, Backspace, Tab outside a table, paste, cut, drop and the letter-style keys change nothing, and a short message comes under the chip (YAZ-4446): "This note is Read only. Press Enter to allow edits.", with a red arrow up at the chip and one red pulse of the chip. While it shows, `Enter` opens the "Allow edits?" box at once (YAZ-4997); that Enter types nothing, and a held Enter opens nothing. Then `Enter` takes the choice with the focus, or `↓` / `↑` move first. A drawing shows "This drawing is Read only." (with the same "Press Enter to allow edits." and the same `Enter`) for a letter, Enter, Backspace, Delete, a paste, a cut, a drop or a double-click on the canvas. The caret keys, ⌘A, ⌘C, the fold keys, zoom and scroll never show it. More tries keep the one message up; it goes about 2.5 s after the last one, and each pane of a split view has its own. It guards against accidents only: comments, reviews, rename, move and delete still work, a column deleted from a folder leaves every note, a read-only one too, and an agent or any other app can still change the file — the open tab shows its change at once. No hotkey and no menu item.
- **Read only for the whole vault** (YAZ-4939): Settings › This vault › **Read only**, Off by default. Turn it On and every note, drawing, diagram, code file and folder page in that vault opens read only — the title, the text, the canvas, every cell and property — with the **Read only** chip and the red card above. The setting is saved in the vault (`.yaseendocs/read-only.json`) and writes nothing into your notes: each note keeps its own Read only. To edit a page, click its chip and pick **Allow edits for 1 minute** (`Enter`), **10 minutes** or **Until I close this tab** (`↓` / `↑` or `Tab` / `⇧Tab` go through the choices and Cancel, `Enter` picks the one with the focus, `Esc` cancels; the same keys in Explore's `E` box, the sidebar lock's box and the "This vault is read only" box, YAZ-4989): that page alone unlocks, the chip turns amber and reads **Editing · 9:52**, counting down, with **Lock now** beside it. At zero the page saves and locks again by itself; your caret stays. From the keyboard (YAZ-4997): in a note, `⌘↵` or `Esc` in the text saves it and locks it again at once, as **Lock now** (the hovers of the chip and of Lock now say so). `Esc` first closes a menu, the find bar, the slash menu or the `[[` picker; only the next one locks, and only a later one goes on down the Esc order (see Sidebar and windows). Inside a code block or a note card's text, `⌘↵` stays theirs. In a page with nothing to lock (the vault and the page not read only), `⌘↵` and `Esc` do what they did before. In Explore, `Esc`, **Done** and `⌘↵` in edit also lock the page again and go back to reading; the next `E` asks again. A drawing or a diagram has no lock key: use **Lock now**. The page cog's **Read only** row shows On while it counts; a click on it then is Lock now. The same three choices come to the chip of a note, drawing or diagram with its own Read only on, in any vault; there the box also keeps **Turn Read only off**, which writes the switch off in the file. In a read-only vault that button is not there: the vault wins, and a page can only be stricter. A folder page in read only (the vault's, or its own ⚙ › Safety › Read only) still lets you change how you look at it, and saves it: sort, filter, group, the columns shown, their width and order, frozen columns, wrap or clip, row height, a calendar's dates, the view tabs and the search. What is in it stays locked: cell values, new rows, a column's name, type or formula, a new column, Fill column, moving or deleting notes. In a read-only note, table sections still collapse and open (the chevron, ⌘↑ / ⌘↓, ⌘⇧U / ⌘⇧I), also in Explore's reading layer; that is not saved to the note while it is locked. Rename, Move (a drag, one row or several), Delete, New note / drawing / diagram / folder, Paste, a Finder drop, today's note, a folder page's New, Duplicate note and Delete note…, and ⌘Z / ⌘⇧Z (or the toast's Undo / Redo) of a move, a rename or a delete in a read-only vault ask first (YAZ-4985) — "This vault (Name) is read only. Allow this file change?" — with **Just this once** (`Enter`: that one action goes, and the vault stays locked), **1 minute**, **10 minutes** (the vault's file actions, that long) and **Cancel** (`Esc`). An action on several files asks once. A Paste of a Cut made in a read-only vault asks that vault too: it would move the file out of it. That vault can be one of this window or one that only another window shows; then its own Read only is read at the paste, and the other window's allowance is not seen here, so it asks (its 1 minute or 10 minutes count in this window). A Paste of a Copy asks only the vault it lands in. An open gesture on a link to a page that is not there (a `[[link]]` pill in a note, in Explore's reading layer, on a drawing or a diagram) and the link picker's Create row make that page: in a read-only vault they ask first, with the same four choices; Cancel makes no page. Delete asks this before its own "Delete …? It moves to the Trash." box, which then comes as always (and not at all with "Ask before deleting" off). **The vault's lock** (YAZ-4985): a read-only vault shows a small grey lock beside its name at the top of the sidebar; a vault that is not read only shows none, and the files look as always. Its hover box says "This vault is read only. Click to allow file changes." A click opens the chip's kind of box: **Allow file changes for 1 minute** (`Enter`), **10 minutes**, **Cancel** (`Esc`). While file changes are allowed — from the lock or from the ask's 1 minute or 10 minutes, the one allowance of the vault — the lock is amber with the time left ("9:52") and **Lock now** beside it; at zero it locks again by itself. The vault's name keeps priority: when the header is too narrow for both, the lock shrinks first to a short time ("10m", "58s") with no **Lock now** beside it, and only then is the name cut to "…"; a click on the lock then offers **Lock now** in its box, which always has it while file changes are allowed (YAZ-4964). With two or more vaults in the window each read-only vault has its own lock there, named in its hover box. A rename asks when you press Enter in its name field, the moment of the change. The app's own writes (IDs, link updates after an allowed rename, the save of a page you unlocked, sync, reviews, the CLI) never ask.
- **Keys**: `Tab` indents. A new sublist is made the way its siblings' sublists are: bullets under one line mean bullets under the next, numbers mean numbers, and with none it is bullets, under a number too (YAZ-3727 D10); into a line that has a sublist, it joins that sublist. `Tab` also moves the first line of a numbered list right under a bullet list (or the reverse): it moves into the line above and takes the kind of its new level (YAZ-3727 D3, D4); with no list line above, it does nothing. `Shift-Tab` outdents (level 1 → paragraph). `Enter` keeps a line's fold, zoom and format: at the start of a bullet it opens an empty bullet above, at the end or in the middle of a parent the rest becomes its first child (after the hidden children when it is folded), on a heading it never makes an empty heading. `Enter` on an empty item outdents. `Backspace` at the start of a line and `Delete` at the end of a line join two lines you can see, also across a bullet list and a numbered list (YAZ-3727 D5): the text joins the line above in that line's format (a bullet, a heading, text or a quote), with one space between words (none right after an Enter), the children stay where they are, and a fold opens rather than hide a line. One `⌘Z` gives back the text and the fold. Next to a horizontal rule the key selects the rule first; a code block or a table never takes the text. `Delete` at a line's start deletes the next character. Typing never leaves the caret inside a folded line: the fold opens, and `⌘Z` closes it again. Empty lines show no "Please enter…" text.
- **Tasks**: `⌘Enter` cycles the item(s) under the selection: bullet → `[ ]` → `[x]` → bullet. On plain text or a heading outside a bullet, it strikes the whole line through (`~~` in the file), and a second press removes the strike (YAZ-3797). A selection moves as one group: every line goes to the step after the line furthest behind, so bullets and text lines are done together (YAZ-3799).
- **Marks**: `⌘U` toggles underline (stored as `<u>text</u>`, like obsidian-underline), `⌘⇧X` toggles strikethrough.
- **Clear formatting** (YAZ-4277 D28, YAZ-4420): `⌘\` takes the letter styles off the selected letters: bold, italic, underline, strike, inline code, highlight and text color. With only a caret, the next letters you type are plain. A heading counts as formatting: it becomes a plain line, and a heading inside a bullet stays in its bullet. Bullets, numbered and check lists, quotes, the indent, links and `[[` pills stay. It is one undo step, over the visible lines only. Read only blocks it. The key is a row of Settings › Hotkeys (`note.clearFormatting`). In a drawing's text box the board's own `⌘\` runs (Reset to default style).
- **Images**: Double-click an image for a full-size lightbox that pages through every image on the page (`←` / `→` or the arrows at the bottom).
- **Lines**: `⇧↓` / `⇧↑` select by whole lines (a line = the paragraph, heading, or bullet text, never a wrapped row): mid-line they first take the rest of this line, from a line edge each press adds exactly one more line, never a piece of the next, and going back undoes one press at a time. Folded or zoomed-away lines are skipped, and nothing hidden is ever deleted: `⌫`, `Delete`, typing and `Enter` over such a selection remove only what you can see. A deleted parent bullet's children move up one level (unfold a parent first to delete it with its children).
- **Line breaks** (YAZ-3727 6C): one line break inside a paragraph (pasted text, or a note from Obsidian or an AI) shows as its own line, as Obsidian shows it; the file is not changed.
- **Zoom**: click a bullet's glyph (or `⌘.` at the caret) to zoom into that subtree, Workflowy-style; breadcrumbs at the top zoom back out (`⌘⇧.` = out one level). View-only — the file is never touched.
- **Zoom history**: every zoom in or out is a step of the window's Back list (YAZ-3647), so Back returns to the level you were at before an accidental zoom, and Forward zooms in again. Back to a page you left brings it back at the level you left it. `⌘Z` right after a zoom reverts it too — `⌘Z` always reverts the single latest view action — bullet fold, heading fold or zoom — and is normal text undo otherwise.
- **A bullet in a new tab** (YAZ-3646): right-click a bullet's dot — or its 6-dot handle — › **Open in new tab**, or ⇧-click the dot, and that bullet opens in a new tab right after this one, zoomed into it, with the same folds and text size; ⌘-click the dot to open it behind, in a background tab. A plain click still zooms in place. These are the defaults of Settings › Hotkeys › **Bullet dots** (YAZ-3936): change any of the three there. The same clicks work on the breadcrumbs: ⇧-click "Trip plan › **Day 1**" to open that level in a new tab, ⌘-click to open it behind; on the first crumb, the page's title, they open the whole page in a new tab (YAZ-3647 E2). ⇧-click on a bullet's text still extends the selection: only the dot opens a tab. The tab keeps the page's name; its tooltip names the bullet too, "Trip plan › Day 1: Lisbon" (YAZ-3647 E4). Back in the new tab returns to the tab you came from, at its level. A task's checkbox: its click still toggles the task; a right-click (or a ⌃-click on a Mac) on it ticks nothing and opens the same menu as a dot (YAZ-3727 D20). The menu's Open in new tab shows no ⇧-click hint (D20). A tab finds its bullet by its text and its count on the page — the second "Lunch" is the second bullet with that text — so if a bullet with the same text above it goes while the page is closed, the tab opens at the next one (a known limit, YAZ-3647 E6). When a note changes outside the app, even a whole rewrite of it, each tab stays at its bullet while that bullet is still there (YAZ-3647 E1); when the bullet is gone, the tab shows the whole page and says so. A bullet typed or renamed a moment ago opens in its new tab too: the page saves first. Change a bullet's text and Back still finds it, even when you go back, or to another page, within a second.
- **Indentation** (YAZ-3727 D1, S1): a list from an AI, from Obsidian or typed by hand nests by its indentation, on open and on paste. A line indented past the line above's marker is its child, however wide the indent (3 spaces under `10.`, a tab, 6 spaces); after a blank line, a paragraph indented that way stays in its item too. The next save writes the usual spacing.
- **Bullet markers**: `-`, `*` and `+` are the same bullet — bullets at the same indent are siblings whatever marker each uses (unified on load; saved as `*` like before).
- **Typing a list marker** (YAZ-3727 D8, D9): on a plain line, type `1. ` (any number) or `* ` / `- ` / `+ ` at the start and the line becomes a numbered line or a bullet. A number starts its list at that number, and joins a numbered list right above when it follows on (`3. ` after `1.` and `2.`); a bullet joins a bullet list right above. `⌘Z` or `⌫` right after gives back the plain text you typed, and `Enter` on it makes a plain new line; a second `⌘Z` removes the typed text. Inside a bullet or a numbered line the marker stays text. `Enter` alone never turns `1.` into a list. Right below a plain line that starts with a written label of the same kind (`2. test`, `2) test`, `* test`), it stays text: that column is written by hand (YAZ-3727 D11).
- **Numbers** look like bullets (YAZ-3727 D7): the same marker colour, and the threading accent on the caret's path. A normal paste of a plain `1.`, `2.`, `3.` list (from a chat app, a web page or plain text) keeps it a real numbered list (D6); any other labels (`3)`, `09.`, gaps, repeats, `a.`) paste as text (YAZ-1429). A line whose whole text is `1. ` or `# ` saves escaped, so it stays a plain line after a reload (B5). On a numbered line, the block menu's "Bullets with written numbers" turns the list into bullets with each number written as text (`3) apples`), one ⌘Z to undo (YAZ-3727 D12). Right-click a line's 6-dot handle (or a bullet's dot) for the toolbar's list buttons in one strip — Bullet list, Numbered list, Checklist, then T (D18): with nothing highlighted they change the whole list the line is in (one level), with text highlighted only the highlighted lines; the lit one takes the lines out of the list. "Number children" shows only on a line that has children (YAZ-3727 D13, D14). A right-click on the line's text shows the same rows after any spelling guesses, above Cut, Copy and Paste (D15); so does one in the gap beside a checkbox (D22). On a line that folds (a bullet with children, or a heading with something under it) the menu also has **Collapse all** (⌘⇧U) and **Expand all** (⌘⇧I), and a right-click on its fold arrow opens the same menu (D23). A right-click on an image in a note shows **Copy image** and **Reveal in Finder** in the app's own menu (D22).
- **Guide lines**: nested lists draw a vertical line under their parent's glyph; clicking a line collapses the parent bullets directly alongside it or fully expands every parent below them, never the line's owner (caret stays put). Settings › Editor › Outline sets them for every note: **Guide lines default** (On / Off), **Guide lines show** (Always show, or Only near the mouse: while the mouse is over the note), and **Guide line darkness** (Light, Medium, Strong, or any value from 5% to 100% with the − / + buttons). The page cog's **Guide lines** row turns them on or off for one note, saved in the note (`guide-lines: false`); that choice wins over the default. Off takes away the line and its click; the chevrons and the fold keys still fold, and Bullet threading still draws the path to the caret.
- **Folding**: the page cog's **Folding** row turns folding off for one note, saved in the note (`folding: false`); Settings › Editor › Outline › **Folding default** sets it for every note with no choice. Off, the note has no chevrons and no Collapse all button, nothing is hidden, and a fold key shows "Folding is off on this page". The note's folds are kept: turn Folding on again and they come back.
- **Drag**: the 6-dot handle moves a block; with several blocks highlighted, grabbing a handle inside the highlight moves them all together (drop position controls nesting depth). Over a guide line or a fold chevron the handle yields, so those clicks always land.
- **Table of contents**: a note with two or more headings shows them at its right edge — as names beside the text when the window has room for them without making the text narrower, else as small lines; put the mouse on the lines and the names open as a card. The names show their level: each level has its own tone, and with the mouse on the names thin lines show which names are below which, with the lines from the current name up to its parents in the accent colour; that accent path also shows while you scroll the note with the wheel. Settings › Editor › Table of contents › **Level lines** (On hover / Always show / Never) says when the lines show. Click a name to go there: the note glides to it, opens any fold in the way and puts the caret on it. `⌘J` does the same from the keyboard (`↑` / `↓` pick, `⏎` goes, `Esc` returns to the note). A name with names under it folds and opens like an outline: click the small arrow left of it, or press `←` / `→`; the chevrons button at the top of the names collapses or expands them all. This folds the list only, never the note, and the folds are remembered per note. ### Code files

A code file opens in a code tab on Monaco, VS Code's editor: line numbers, fold arrows, sticky scroll, coloured bracket pairs, Monaco's find box (⌘F), and saves that keep the file's line break and BOM.

- **Which files**: the code and text types (`.ts`, `.py`, `.json`, `.yaml`, `.lua`, `.elm`, …), and these well-known names with no extension, spelled exactly so: `Dockerfile` (and `Dockerfile.dev`, `Dockerfile.<anything>`), `Makefile`, `Procfile`, `Gemfile`, `Jenkinsfile`, `Vagrantfile`, `LICENSE`, `CODEOWNERS`. Dot-files (`.gitignore`, `.env`) stay hidden.
- **Fold keys**: the note's built-in fold keys (listed in Settings › Hotkeys) fold the code too: ⌘⇧U collapses every block, ⌘⇧I expands them all, ⌘↑ folds the block at the cursor and ⌘↓ opens it (so ⌘Home / ⌘End go to the top / bottom). A right-click on a fold arrow shows **Collapse all** and **Expand all**. The double chevron left of the page cog does the same in one click, as in a note. Folds are remembered per file. Monaco's own right-click menu inside the code keeps its items, in the app's menu look.
- **Colours**: Monaco's own languages, plus small tokenizers for the types Monaco lacks: Haskell, diff and patch, Groovy and Gradle, Erlang, CMake, Elm, and `Makefile`. A `Dockerfile` is Monaco's Dockerfile, `Gemfile` and `Vagrantfile` are Ruby, `Jenkinsfile` is Groovy; `Procfile`, `LICENSE` and `CODEOWNERS` are plain text.

### Table of contents of a code file

A code file shows its **table of contents** where a note shows its own: at the tab's right edge, on the same settings (Settings › Editor › Table of contents: Table of contents default, Pin default) and the same width. It has every feature of VS Code's Outline, in the app's look. The page cog's **Table of contents** row (the default until you click it) turns it on or off for this file only, remembered with the file in the app state file (on this Mac), as a note's row is; the cog's other rows sit under the heading **All code files**, since they change every code file. With Pin default Off the names show when 800 px of code still fit beside them; else small lines, and the mouse on them (or ⌘J) opens the card. **Pin** in the card is Pin default On.

- **Rows**: every symbol of the file, nested as a tree with no depth limit — classes, methods, functions, constructors, interfaces, types, enums and their members, variables, constants, fields, properties. A type icon on each row. A variable or constant declared inside a function, method or arrow function (a loop counter `n`) is not a row: the file's top-level and namespace variables are. A ⌄ on each row with children collapses it; **Collapse all** at the top.
- **Filter**: the box at the top keeps the rows that hold the typed text and their parents.
- **Collapse all / Expand all**: the chevrons button beside the filter collapses every row with children while one is open, and expands them all once all are collapsed.
- **"…" menu**: **Sort by** Position (the default), Name or Type; **Show** turns each kind of symbol of this file on or off (all on by default, as in VS Code; a hidden kind hides its children too), and, when the file has some, **Variables inside functions** (off by default) brings the names inside functions back; Expand all, Collapse all. Sort by and Show are remembered for every code file.
- **Follow the cursor**: the row that holds the cursor is the accent colour (while you scroll with the cursor off screen, the row at the top of the view), and the list keeps it in view.
- **Error marks**: a row whose code has an error or a warning shows a red or yellow dot; a collapsed row shows the worst one it hides.
- **Go to a row**: a click glides the code to the symbol, opens any fold in the way, and puts the cursor on its name. ⌘J from the keyboard: type to filter, `↑` / `↓` pick, `⏎` goes, `Esc` clears the filter and returns to the code; `←` / `→` collapse and open the picked row while the filter is empty.

The symbols are Monaco's own for TS, JS, React, JSON, CSS and HTML. A Python file's are read from its text (`class`, `def`, `async def`, decorators, top-level `UPPER_CASE` constants): no language helper is needed. A file with neither (`.lua`, …) shows no table of contents. The table of contents reads the symbols 300 ms after the last edit, never on a keystroke, and draws only the rows on screen. For TS, JS and React files the background worker that reads the symbols also builds the whole list, so typing in a 5 MB file stays smooth (each key draws within one frame). View-only — the file is never touched.

**A large code file** (512 KB or more): sticky scroll pins the lines that start each indented block (Monaco's indentation model), not the symbols, so typing stays smooth; in code indented as usual it pins the same lines. Colour swatches and clickable links are off in it: each one found in a large CSS, JSON or HTML file slowed the typing. Everything else stays on: syntax colours, folds, errors, bracket colours, and the table of contents of a TS, JS or React file. A large file of any other language has no table of contents: its symbols would be read on the page and slow the typing.

### Jump by meaning in code files

A code file that opens in a tab (TS, JS, React, Python) gets VS Code's two jumps. Across files, they need one switch: Settings › Code › **Jump across files (Cmd+click, Shift+F12)**, off by default. With it off, no language helper runs, and both jumps work inside the one file (Monaco's own help, at no cost).

- **The first switch-on** shows a box: "Turn on jump across files?", what the jumps do, and that they need two helper tools (about 15 MB) that run only while a code file is open. **Cancel** keeps the switch off and downloads nothing. **Download and turn on** downloads the pinned helpers (TypeScript 7 for this computer and `pyright`) from the npm registry, checks each one against the sha512 pinned in the app, unpacks it into the app's data folder (`<userData>/lsp/`), and then turns the switch on; the box shows each step. Offline, a failed download or a file that does not match ("The download did not match. Try again later.") says why in the box, keeps the switch off and leaves no half folder. A later switch-on, with the helpers there, shows no box.
- **Off again**, with code tabs open, stops every helper within 2 seconds.

With the switch on:

- **Cmd+click** (or F12) on a name opens the file where it is made, in the same tab, at its line. Back returns to the place you left, with the cursor and the scroll, and Forward to the target's. A target in the project's `node_modules` (a `.d.ts`) opens in a code tab too.
- **Shift+F12** (or right-click › Find All References) opens VS Code's peek box with every place that uses the name. Enter or a double click on a row opens that place.

A language helper answers, one for each project, in its own process: TypeScript 7 for TS, JS and React (the project is the nearest `tsconfig.json`, `jsconfig.json` or `package.json` above the file), and `pyright` for Python (the nearest `pyproject.toml`, `setup.py` or `requirements.txt`, else the vault). `pyright` runs on the app's own Node: Python itself needs no install. When the project has a `.venv` or `venv`, Cmd+click also opens the installed libraries, and the source of an editable install (a `.pth` line). The app never runs the project's own Python (a folder from someone else can hold a fake one): it reads the venv's library folders from disk instead, and no folder of the project is on the helper's `PATH`. With no venv, library jumps need a `python3` on the app's `PATH` outside `/usr/bin` (an app opened from the Finder has none), and jumps inside the project always work. `/usr/bin` is left out on purpose: on a Mac without the Command Line Tools, `/usr/bin/python3` opens Apple's install dialog. Hover on a Python name shows its type. While the switch is on, a helper starts with the first code tab of its project and stops when the last one closes. At most 3 helpers run at once; a 4th project stops the one used longest ago. While no helper answers (a file outside any project, a helper that is still loading or that crashed), the jumps work inside the one file, with no message.

Limits:

- TypeScript 7 does not read `baseUrl`. A project whose `tsconfig.json` uses `baseUrl`, or a `paths` entry without `./` or `../`, loses the jumps through those imports (relative imports still work). Write `paths` relative to the `tsconfig.json`, with no `baseUrl`: `"@shared/*": ["../shared/*"]`.
- A helper sees only its own project. In a folder with several `tsconfig.json` files, Shift+F12 lists the places in the project of the tab, not in the others.
- A name made in the helper's own files (`console`, `Array`, Python's `print`: the `lib.*.d.ts` and stub files inside the downloaded helpers) does not open. A `.pyi` stub file does not open either.

### Comments

Every note carries a Linear-style comment stream under its body, before "Linked mentions". It lives in the note's own frontmatter, under one `comments` key, so it travels with the file (sync, rename, Obsidian); no sidecar, nothing else is written. A folder has the same stream under its views, kept in the folder's hidden `.folder.md` (see Folders). Threads are one level deep (a reply names its top-level parent in `reply_to`; a reply to a reply is filed under the root), a comment can carry an optional one-line title, every comment wears a stable number (`#3`, a reply `#3.1`) that never changes, even after a delete, and folds like a bullet without its header text ever moving (Expand all / Collapse all on the header), and bodies are GitHub-flavoured Markdown, rendered read-only and sanitised. The Properties panel shows the key as Reserved, and it never enters the index or a view column. `⌘Enter` posts; Delete asks first.

For agents: the app ships a command, `yaseendocs` (in the packaged app, `Yaseen Docs.app/Contents/Resources/bin/yaseendocs`). Give the agent the command and a page's path — right-click the page › **Copy path**; a folder's page is the `.folder.md` inside it. The agent runs `--help` and learns the rest: `yaseendocs comment "<page.md>" --body "…"` (with `--title`, `--reply-to`, `--by`), `comments` (`--json` for the threads), `edit` and `delete` — the last two only on comments an agent wrote (`by`), never yours. `yaseendocs mentions "<page.md>"` (`--json` for a script) lists the notes and folders that link to the page, the same pages as its Linked mentions, in every vault. It writes exactly what the app writes. Three verbs take no page (YAZ-4269): `yaseendocs vaults` lists the vaults the app knows (`--json` for a script), and only reads. `yaseendocs daily <vault>` finds the daily note of today (or `--date today|tomorrow|yesterday|YYYY-MM-DD`, the Mac's own day) and makes it when there is none, by the app's Daily notes settings — also the newest ones from another Mac in the settings folder — and the daily notes folder's template; `--find` never makes one, and `--open` then opens it in the app as its `yaseendocs://` link does (the window of its vault comes to the front; no scroll to the current time). `yaseendocs new <folder> --title <t>` makes a note as New note does (`--body` for its first text, `-` for stdin); a note of that title already in the folder is the answer. Both work with the app closed, print `made <path>` or `found <path>`, warn about any other note of the same title, and never make two notes at one moment — the app's button and the command share one lock on the Mac. Without the command, append a comment by hand: `by: agent`, `n` one past the highest in its run — the page's top-level comments, or that parent's replies — and quote the `id` if it happens to be all digits:

comments:
  - id: 3f9a1c2e
    n: 1
    at: 2026-09-11T18:22:31Z
    by: agent
    title: Numbers check
    body: The Q3 figure in the second table is off by one row.

### Note cards (YAZ-4946)

A **note card** is a spaced-repetition card that lives in a page, in a vault that gives its notes IDs. It is a ```` ```card ```` block: `---` alone on a line splits the front from the back, and `{{word}}` hides a word (Mochi's `{{1::word}}` reads the same; all hidden words of a card are one review). Code in a card (a code block or `code`) stays as written: a `{{word}}` or a `---` there hides and splits nothing. The card's first line is its title, in the card window and in lists. Under the block, one line keeps the card's ID and its reviews, `<!-- card: WIKI-512, 2026-11-12T14:05Z good, … -->`, so the card and its history move together; GitHub and Obsidian hide it. A card ID is the vault's next number, from the same counter as notes and drawings. A card with no ID gets one. A copy you paste (or drop) on a page that already holds that card gets a new ID at once and starts with no history, above or below the original: the card that was there keeps its ID and its history. A card you move on the page (cut and paste, drag) keeps both, and so does a card cut from one page and pasted into another; one still on two pages a minute after a paste is a copy, and the page that held it last gives its copy a new ID with no history. A copy an agent or git writes into a page is settled the same way, and its history is never emptied unless it is the same card twice. In a vault that does not give IDs a ```` ```card ```` block is a plain code block. Links, tags and backlinks inside a card work as in the page, and a rename updates them.

### Card files (YAZ-5037)

A card can be its **own file**, next to pages, drawings and diagrams, in a vault that gives IDs, while Settings › Review is on. It is a normal `.md` file with `kind: card` in its properties (hidden in the panel) and one card. The card's ID is the file's ID, its first line is the title, and its name is `<title>-<id>.md`, as a page's.

- **New card**: right-click a folder (or the "New …" menu) › **New card**, after New page. ### The card skill (YAZ-5059)

A guide for you and your AI agent on how to make good cards. It ships with the app as plain pages (`skills/card-skill` in the repo). At each start after an update, before a window opens, the app copies it to `<app data>/card-skill` (`~/Library/Application Support/Yaseen Docs/card-skill`) and uses only that copy. The copy is read only on disk, and the next update replaces it whole: to change the skill, duplicate it into your vault.

## Two kinds of vault

A vault is one of two kinds. A folder you open is a **plain** vault: the app asks nothing and writes nothing you did not ask for. IDs are a setting, for the vault where you want them: Settings › Files & Links › **Give this vault's notes IDs**.

- **IDs on**: every note gets a permanent ID, the app names each note's file from its title and its ID, and links keep working when a note is renamed or moved, by anything. Everything below about titles, built file names, IDs, shortcuts, each folder's own properties and the default Board and `status` column describes this kind of vault.
- **IDs off** (how every folder starts): the app is a plain viewer and editor of the files you have, and it never writes anything you did not ask for: no IDs, no `title:` lines, no hidden files in your folders. A note's name is its file name: a new note is `Name.md`, a rename renames the file and updates the links that named it, and a copy is `Name copy.md`. Folder pages and tables still work: a folder opens as a Table whose columns are the notes' own properties, and editing a cell changes that one line in that one note. Shortcuts, per-folder properties, deleting a column, Copy ID and search by ID are not offered.

Click **On** and a box asks first. It says what an ID is, how many notes and folders the app will write to, and how to undo it, and it has a text field: type the vault's **ID letters**, 2 to 5 letters such as `YAZ`. "Give IDs" does nothing until the letters are typed; Cancel or Esc writes nothing. A vault where every note and folder already has its ID turns on by itself.

The answer and the letters are kept in the vault itself, in `.yaseendocs/ids.json`, so your other machines get the same ones. You can change the answer at any time. Turning it on gives the notes their IDs then. Turning it off stops the app writing from then on and removes nothing; notes show their file names, and links stored as IDs do not open, until you turn it back on.

A note's ID is the vault's letters and a number, like `YAZ-12`: the next number of the vault, so you can say it, type it and remember it. It is in the note's `id:` line, in each link to the note (`[[YAZ-12]]`) and in its file name (`my-note-yaz-12.md`). A number that a deleted note had is not used again. Each Mac keeps its own count in the vault, in `.yaseendocs/ids/`, so two Macs that sync the vault never change the same file. The 12-character IDs that older versions gave (`6cbnmcq5n2sj`) still work everywhere, and the app never changes one unless you ask: Settings › **Old IDs** › "Give them numbers" gives each of those notes the next number, and its links and file name follow.

With IDs on, the same group of Settings has three more rows.

- **ID letters**: "Change letters" changes the letters in every note's ID, in each link to a note of this vault and in each file name. A link to a note this vault does not hold keeps its letters. The numbers stay, and a link with the old letters still opens its note. Do it on one Mac, while the vault is synced and closed on the others.
- **Duplicate IDs**: two Macs that have not synced yet can give two notes the same number. The app fixes that by itself after the sync: the older note keeps the number, the Mac that made the newer note gives it the next one and updates the links it wrote, and a notice says what changed (`YAZ-101 was used on two Macs. "Bar" is now YAZ-102. 1 link updated.`). "Check for duplicates" runs the same check now.
- **Old IDs**: shown while a note still has a 12-character ID, or while a run that gives them numbers stopped before its end. "Give them numbers" gives each such note the next number, oldest file first, and its links and its file name follow. Sync the vault and close it on the other Macs first.

**Notes that already have IDs** (YAZ-4922): when you turn IDs on in a folder whose notes already hold number IDs (for example a folder cut out of another vault), the box says how many notes and folders hold which letters ("23 notes and folders have an ID with YAS") and offers **Keep YAS** first, the biggest group. Keep writes `.yaseendocs/ids.json` only: no note changes, and every link still opens its note. A smaller group with other letters (`TECH-796`) is kept as it is too: its IDs stay, and only a note with no ID gets a number. Type other letters instead and **Use** them: each ID of the biggest group takes the new letters, its number stays, and each link and file name follows, as "Change letters" does. A note that has a number never gets a fresh one.

**A vault inside a vault** (YAZ-4922): each note gets its ID from one vault only, the nearest folder above it that has its own IDs answer (`.yaseendocs/ids.json`). The outer vault still shows the inner vault's notes in its sidebar, search and links, but it never gives, changes or counts their IDs, and the inner vault never touches the notes outside it. With the same letters in both, the inner vault counts above the outer vault's numbers, so two notes never share a number. A note you make inside the inner folder takes the inner vault's next ID.

A file that arrives with no ID (an agent wrote it, or you dropped it in Finder) gets its number from one Mac only: the vault's first Mac (the one whose count file in `.yaseendocs/ids/` is oldest) does it at once, and every other Mac waits 10 minutes and does it only if the file still has none. So two Macs never write two numbers into one file.

**What this vault calls a note** (YAZ-4938): Settings › Files & Links › This vault › **Call a note a …**: **Note** (the default) · **Card** · **Doc** · **Page** · **Your own word** (one word and its plural, like Entry / Entries). Every place the app names the thing you make and open follows it: "New card", "Delete card…", "Duplicate card", "12 cards", "No cards here.", the folder page's "+ New", the toasts, the explore layer's words and the Settings labels. The choice is saved in the vault (`.yaseendocs/unit-word.json`), so each vault has its own flavour and your other Macs get the same word; a window with two vaults uses each vault's word for its own items. Feature names keep theirs ("Cell note", "Daily notes", "All notes", "Notes from"), the help docs stay as written, and a card is still a `.md` file.

## Sidebar and windows

- **Three tabs**: the sidebar shows your vault three ways, switched by the tabs at the top (the fifth tab, the stack, is your saved **Sessions**, and the sixth, the clock, your **Recents** — both below). **Files** (the default, YAZ-1846) is the ordinary folder tree on disk — every file, not just the ones the app can open: a file with no in-app viewer (an EPUB, a ZIP, …) is listed muted and a click hands it to the OS default app, as does right-click → Open in ▸ "Default app" on any row. A folder is itself a page: right-click it → **Open folder page** to open it (see Folders). The **eye** tab is your focus list and the **♥** tab is your favorites (both below). Same vault, three readings; all offer the same right-click menu.
- **Create**: right-click a folder, a file, or the blank space under the tree → "New note", "New drawing" or "New folder". A click makes the everyday kind: a note, an Excalidraw drawing, a folder. Hold the pointer on the row for its list: "New note" / "New dated note", "New Excalidraw drawing" / "New dated Excalidraw drawing" / "New draw.io diagram", "New folder" / "New dated folder" (the dated ones come pre-titled with today's `MM_DD- `, cursor ready for the rest; there is no dated diagram). A drawing or diagram is named by what you type — an empty box is `Untitled`, then `Untitled 2` — has no note ID, and opens in a tab (YAZ-3028 D9); type its title inline (Enter confirms, Esc cancels). A title is free text and is kept in the note's own frontmatter as `title:` (a folder's in its `.folder.md`); the name on disk is built from it by the app, never typed: a note's file is its title in kebab-case plus the note's id (`UP-001 - Abdul Sample R` → `up-001-abdul-sample-r-yaz-12.md`), a folder's is its title in kebab-case (`Upwork 2026` → `upwork-2026/`). Two notes can share a title; their ids keep the files apart. Notes open at once, starting from the folder's template when it has one (a hidden `.template.md` in that folder); nothing is ever overwritten.
- **Rename and delete**: both are in the same right-click menu, on every tab. Renaming a note or a folder edits its title inline — the same edit as the title at the top of its page, or a double-click on its name in a table: the `title:` line is rewritten, the file or folder is renamed to match (a note keeps its id), and every `[[link]]` that spelled the old title follows it across the vault (a summary notice says how many; links the app wrote are by id and need no update). Any other file is renamed by its name. Deleting moves the file to the system Trash — never a permanent delete — and closes its tabs. Select rows and press `⌘⌫` to delete them, as Finder's Move to Trash does (YAZ-3272); a plain `⌫` deletes nothing. `⌘⌫` and the menu's **Delete** take the whole selection when the row is in it ("Delete 1 folder and 2 files"), and a row inside a selected folder goes with the folder. The question names one item or counts them ("Delete 3 items? They move to the Trash. 2 notes link to them."), and `⏎` confirms; with **Confirm before deleting** off it deletes at once. All the items go as one step: one trash sound, "Deleted 3 files (Todo.md, Plan.md, Budget.md)" with **Undo**, and one `⌘Z` puts them all back. A failure on one does not stop the rest, and one notice says both. In a note, a drawing, a diagram, a field or a dialog `⌘⌫` keeps its own meaning; a selection that holds a vault row deletes nothing. A rename or move done OUTSIDE the app (Finder, sync) is detected too and offers to repair the links, always confirm-first. The app never renames a file it did not name: a note made elsewhere keeps its file name, and shows it as its title, until you edit its title in the app; a `title:` you or an agent write by hand shows at once and renames nothing.
- **Cut, copy, paste**: right-click a row (or a selection) → **Cut** / **Copy**, then right-click a folder → **Paste** (`⌘X` / `⌘C` / `⌘V` do the same on the selected rows; `⌘V` pastes into the selected folder, beside the selected file, or into the vault root when nothing is selected; with several vaults in the window, select a vault or a folder first). On a board or a diagram, `⌘C` / `⌘X` / `⌘V` belong to the page: a board copies and pastes its own shapes and the picture or text on the clipboard, never a copied file (YAZ-4372). One clipboard for the whole app, so you can copy in one window and paste into another vault's window. A copied note is its own note at once — a fresh id, the title "<title> copy" and a file name built from both — so pasting into the same folder is how you duplicate; a copied folder is "<title> copy", every note in it gets its own id, and each keeps its values; any other file that lands on an existing name becomes "Photo copy.png", then "Photo copy 2.png". A cut never overwrites, moves tabs and links along like drag-drop, and pastes once. Folders copy whole. The menu itself is six groups: open, clipboard, new, this row, favorites + **Open in ▸** (new window, VS Code, default app, Finder), delete.
- **Search**: `⌘K` searches note titles and aliases across the vault — across every vault in the window — from the sidebar. It finds a name by its words too, in any order and across hyphens: `yaseen workflow` finds `1-yaseen-engineering-workflow`, and `workinglog` finds `Working Log`; each matched part is marked. A note whose file name you gave by hand (`2026-10-28-sync.md` titled "Weekly sync") is found by that file name too; ↑/↓ pick, Enter opens, ⌘-Enter opens in a background tab. The key is a toggle (YAZ-4994): press `⌘K` again while the keyboard is in the search, and you are back on the page where you were, with no scroll; the sidebar shows its last tab again, or closes again when `⌘K` opened it. With the keyboard back in the page, `⌘K` goes into the search again. A key you bind to Search the vault in Settings › Hotkeys toggles the same way. Type a note's number — `12`, `YAZ-12`, `yaz12` or `yaz 12` all find `YAZ-12` — or paste anything that holds an ID: a `[[link]]`, a file name, an old copied path. That note or folder is the first result, and the title matches for the same text come after it. Type `#` and a number to search by the ID number alone (YAZ-2571): `#5` finds EMB-5 and nothing else, and `#3` finds EMB-3 first, then EMB-30 to EMB-39, in number order; in a vault without IDs `#5` is ordinary text. A result found by its ID always shows the ID, with the matched digits marked as matched letters of a name are; in Explore a long name is cut with "…" and the ID stays. In a vault with IDs, Settings › Files & Links › **This vault › Show IDs in search** (YAZ-4940) says when a result shows its ID: **Always** (the default: `s3` shows "WIKI-38 — S3 (AWS)" too), or **Only when the search matches the ID** (the quieter sidebar of before). The same choice rules the Explore search's ID chip. Saved in the vault. Two more rows in the same block (YAZ-4940 part 2): **Show IDs in the title** (On by default) draws the note's ID after its title, small and muted ("DNS basics  EMB-46"), in the note and in Explore's note layer; a click on it copies the ID ("Copied EMB-46"); it is drawn, never part of the title, never written to the note, and a long title sends it to the next line by itself. **Show IDs in the files list** — **Off** (the default) · **Number (#12)** · **Full ID (EMB-12)** — puts the ID at the right end of each note's row in the sidebar's Files, Focus and Favorites, so the IDs line up in a column and the names stay where they are. Number shows "#" and the ID's number alone (the letters are the same on every row; the title, search and Explore keep the full ID; an ID with no number part shows in full); a vault that had this row On reads it as Number. A long name is cut with "…" and the ID always stays; a folder row shows none. Both are saved in the vault with the search choice.
- **Explore the vault** (YAZ-2571, Mochi-style): `⌘⇧F` (or File › Explore Vault…) opens a search panel in the middle of the window, with the caret in it, in every vault — with or without IDs; `⌘K` keeps the sidebar search. Each result shows its icon, title and folder; ↑/↓ pick, `↵` opens. The note opens **on top of the search**, for reading, and the search stays under it. Press `E` or click **Edit** to edit it in the same panel, with the app's normal saving. `⌘⇧F` again adds a new search on top of the open panels (YAZ-4994: Yaseen kept this; only `⌘K` toggles); a click on a link in a note adds that note on top. Each panel sits a little right of the one under it, so the trail shows. `Esc` closes one panel at a time, the top one, and the panel under it is exactly where you left it, scrolled to the same place; the last `Esc` returns you to the page, which never moved: it stays where you scrolled, not at its caret (YAZ-4971; also ×, `⇧Esc` and a click outside). `⌘↵` (or ↗) opens the top note in a normal tab and closes the stack. In the search, `⌘↵` opens the highlighted result (a note, a board, a folder) in a tab (YAZ-4984). While a note is in edit, `⌘↵` saves it and goes back to reading — in a read-only vault it also locks the page again at once, as **Lock now**, and so do `Esc` and **Done** (YAZ-4997) — and the next `⌘↵` opens the tab (YAZ-4988; the head shows **Done** `esc` `⌘↵`). Inside a code block `⌘↵` stays the code's (a new line); on a note card it goes back to reading (Open card is in the card's ⋯); in the text it replaces the note's own `⌘↵` (the task box, a line below a table) while in Explore. A folder (or a PDF) from the list opens in a new tab. **Drawings and diagrams** (YAZ-4943) open in Explore too, for reading: the search finds them by name, and they open from a result, ‹ ›, a link in a note, a link on another board and the recents. The board fills its panel, fitted; scroll or drag to move it, ⌘ + scroll (or pinch) to zoom, click the % to fit it again. A diagram shows its pages as tabs under it. A click on a link on the board opens that note or board on top. Nothing is ever saved, and there is no Edit: press `↗` (or `⌘↵`) to edit it in a tab. A board panel moves, resizes and stacks like a note panel. Twelve panels at most. In a diagram, `⌘⇧F` is also draw.io's "To front": Explore takes it by default, and the `⌘⇧F` card in Settings › Hotkeys can give it back to draw.io. In an ID vault each result shows the note's id after its title. A reading layer shows what the note's tab shows: board embeds as windows, pills with icons, pictures, and under the note its **Comments** and **Linked mentions** (a mention opens on top); the head has the note's collapse / expand button, **Edit** (`E`) and, while editing, **Done** (`Esc`): Esc goes back one step, out of edit first (the note saved as you typed), then the layer. A note you opened from a search has **‹ 2/3 ›** in its head: `→` / `←` while reading (or `⌘⌥↓` / `⌘⌥↑` in any mode; Settings › Hotkeys › Explore) go to the next or previous result of that search, in the same panel; while editing, the note saves first. Esc goes back to the search with the result you stopped on selected. A note opened from a link has no ‹ ›; a new search on top starts a new ‹ ›. Every panel moves like a cell note: drag a note's head (a search's top edge) to move it, drag an edge or a corner to resize it, double-click the head to put it back; a new panel opens next to the one under it, wherever that is now; the first panel's place and size are kept for the window. A note panel's head has the page's **zoom** pill (− 100% +; click the number for the presets or type a value); `⌘+` / `⌘−` / `⌘0` zoom the top note panel while Explore is open, never the page behind. One zoom for every Explore note, kept after a restart; a note tab keeps its own. The layers act like windows: a click on a layer behind brings it to the front, with its place, scroll, search and zoom kept, so you can read two notes (or a note and its search) side by side; its × closes that layer only and its head drags it; the keys go to the front layer, and `Esc` closes the front layer (the one you used last), then the next. From two layers on, a **trail** of chips at the top ("Search › TCP handshake › DNS basics") shows each layer, the front one bold; a click on a chip brings that layer to the front, and no layer closes. At the end of the trail, **▦ Tile** arranges the open notes and boards in one click (YAZ-4944): 2 side by side, 3 across, 4 in a grid, 5 in a grid with one in the middle; with more than 5 open, the 5 you used last. The **▾** beside it opens **Arrange**: pick a layout (Side by side, Three, Grid, Grid + centre, Stack) and which windows go in it (the newest are checked; "Include searches" adds the searches), then `↵`. Keys: `⌥⌘2`, `⌥⌘3`, `⌥⌘4`, `⌥⌘5`, and `⌥⌘0` to put every window back in the stack (Settings › Hotkeys › Explore; while a note is in edit, those keys stay the note's headings). The windows glide to their places, with even gaps, and stay windows: drag, resize, bring to front or close each one. The head no longer says "Reading"; "Edit E" is there when you can edit. `⇧Esc` closes every layer at once, a note in edit saved first, and the caret is back where it was. `⌘F` in a reading layer finds in that note. A right-click on a result, on a layer's head or in a reading note's text gives the **note menu**: Open in new tab · Open in new window · Open in mini window — Show in sidebar · Add to focus › · Copy path — Rename file — Add to favorites › · Reveal in Finder · Open in VS Code (the opens, Show in sidebar and Rename file close the stack). A note renamed elsewhere follows in its layer; a deleted one says it is gone. **Open in Explore** (YAZ-4936): right-click a pill to a note, a `[[link]]` or a `[text](note.md)` link, › **Open in Explore**: the note reads in a layer with no search under it; Esc closes it and the caret is back. Settings › Files & Links › **This vault › Clicking a link**: **Opens the note** (the default) or **Opens it in Explore**, saved in the vault; with Explore a plain click on a note pill opens the reading layer, `⌘`-click and the other keys keep their doors, and a board or a folder pill keeps its click. **A narrow layer** (tiled, or dragged narrow) folds its head one part at a time into **⋯** (YAZ-4986): first the zoom pill, then Collapse all, ‹ 2/3 ›, ↗, the Read only chip's word (its lock stays), the chip, and Edit / Done last. The title (cut with "…"), the ID and × always stay; ⋯ holds every action of the head. Board and card layers fold the same way, and keep their ID. **A page that changes** while Explore is open (YAZ-4990): a reading layer shows the new text by itself after the save, at the same scroll place and with its folds; a page deleted outside the app says it is gone (after a short check, so a tool that saves through a temporary file does not trip it); a note in edit was already live. In the search, the highlight stays on its note when results come or go above it. A sheet that opens while Explore shows (Rename, Delete, "This vault is read only") and a toast with Undo stand on top of Explore (YAZ-4987).
- **Esc closes one thing at a time; the sidebar is last** (YAZ-4995): each Esc closes ONE thing, the top one first. 1. A menu, a popover, the slash menu, the `[[` link picker or the find bar. 2. A dialog or a sheet. 3. An Explore layer, one at a time; in a page you unlocked for a time ("Editing · 9:52"), Esc saves it and locks it again first (YAZ-4997). 4. The Inbox. 5. The sidebar's search: it goes back to the tab you came from (Files), with the keyboard on the open page's row. 6. The left sidebar closes, and the page has the keyboard, with no scroll. So `⌘K`, then Esc, shows the files; Esc again closes the sidebar. Esc with the caret in the page text, or in any field, never closes the sidebar (in an editable note, Esc there moves the keyboard to the sidebar, as before, and the next Esc closes it). Esc never opens the sidebar: `⌘⇧B` (or your Toggle sidebar key) does. A Files window keeps its sidebar: there Esc on a row goes to the page, as before.
- **Move by drag**: drag a file or a folder onto a folder, a vault row or the header (the vault root). Drag a selected row and the whole selection goes, in the order you see it; a row inside a dragged folder goes with the folder. Drop on a file and the items land in that file's folder. Hold a drag over a closed folder for a moment and it opens. Links and open tabs follow, as with Cut and Paste. A note keeps its values, so a move asks nothing. A name that is taken in the target stays where it is, and the toast names it. Between two vaults, use cut and paste.
- **From and to Finder**: drop files and folders from Finder onto a folder, a vault row, a file row or the header and they **move** into the vault; from another disk they are copied, as Finder does. Hidden files (`.DS_Store`) are skipped. Drag rows out of the sidebar into Finder and Finder gets **copies**; the vault keeps its files. The moment you let go of the mouse, a box shows at the bottom and asks "Copied 2 files (Todo.md, Plan.md) to Finder?", with **Remove from vault** (the items go to the Trash) and ✕ or `Esc` (keep them). The box asks every time the drag ends outside the window, because the app cannot tell a drop in Finder from a cancelled drag. On macOS the app watches the mouse button after a drag out, so the box does not wait for the pointer to come back over the window (YAZ-3294); if that watch cannot run, the box shows when the pointer comes back. A drag that ends inside the window asks nothing. **Remove from vault** looks again first: an item that another window moved or deleted meanwhile is left alone. A Finder folder that holds a vault you have open does not move in.
- **Copy and paste with Finder**: `⌘C` files or folders in Finder, then `⌘V` in the sidebar: they are copied into the selected folder, beside the selected file, or into the vault root when nothing is selected (with several vaults, select a vault or a folder first). Right-click a folder → **Paste N items** does the same. Finder keeps the originals. Each item keeps its own name; a name already there becomes "Report copy.pdf", as in Finder. A folder comes with all it holds, and hidden files (`.DS_Store`) are skipped. The other way, `⌘C` or `⌘X` rows in the sidebar, then `⌘V` in Finder: Finder pastes copies (a cut still waits for a paste in the app). The newer copy wins: copy in Finder after the app and Finder's files paste; copy in the app after Finder and the app's own clip pastes. Copy anything else after the app's copy (text, a screenshot, a picture from a browser) and no file pastes, as in Finder: the copied files are gone from the clipboard (YAZ-4372). These pastes are copies, so `⌘Z` does not take them back. macOS only.
- **Undo a move**: `⌘Z` puts back the last move: a drag, a Paste of a Cut, or a move in from Finder (those go back to their Finder folder). All the items of that move go back, and their links follow. `⌘⇧Z` does the move again, with no question. The toast after a move says "Moved 2 files (Todo.md, Plan.md)" with **Undo**, and after an undo "Moved back 2 files (Todo.md, Plan.md)" with **Redo**, each followed by the links that were updated, as "Updated links in 1 note"; both fade after 6 seconds (or the longer time set in Settings › Notifications › **Show for**), and the keys still work after that. Every toast of a move, a paste, a drop from Finder, a delete or an undo says "file" or "folder" and names its items as they are on disk, with the extension, in the order of the gesture: the kinds first, then up to 3 names, then how many more ("Moved 1 folder and 2 files (Projects, Todo.md, Plan.md)", "Moved 12 files (a.md, b.md, c.md + 9 more)", YAZ-3274, YAZ-3293). In a vault that uses IDs the name on disk holds the ID, as Finder shows it. The Cut and Copy notices and the menu's counted labels say the kinds alone ("Cut 2 files", "Delete 1 folder and 2 files"); **Paste N items** still counts items. An item that changed since (moved, renamed or deleted) stays where it is, and the toast says "Can't undo: Plan moved again"; the rest go back. Each window keeps its own list of the last 20 steps, for the session only: moves, and renames and deletes (next item). Copies are not in it. In a note, a drawing, a diagram, a field or a dialog, `⌘Z` and `⌘⇧Z` undo and redo there as always. An undo that could not run for a passing reason (the disk was busy) stays on the list, so the next `⌘Z` tries again. When the window's vaults change (a vault leaves the window, or one is added), the list empties, and a toast still on screen loses its **Undo** or **Redo** button.
- **Undo a delete or a rename**: the same list, newest first, one step per `⌘Z` (YAZ-3268). After **Delete** the toast says "Deleted 1 file (Plan.md)" (or "Deleted 1 folder and 2 files (Plan, Todo.md, Budget.md)" after a Delete of 3 rows or **Remove from vault**, each one step) with **Undo**; `⌘Z` takes each item back out of the Trash to its old place, with the "Volume Mount" sound: "Put back 1 folder and 2 files (Plan, Todo.md, Budget.md)" with **Redo**. `⌘⇧Z` sends them to the Trash again. An item that left the Trash says "Can't undo: Plan is no longer in the Trash"; one whose old name a new file took stays in the Trash: "Can't undo: a file named Plan is there now"; the rest come back. When the app could not find the item in the Trash, the delete still works, but its toast has no **Undo**. After a rename — in the sidebar, the page title, a table's Name cell, a title edit — the toast says `Renamed to "Plan v2"` with **Undo**; `⌘Z` gives the old name or title back with no question, and links follow back: `Renamed back to "Plan"` with **Redo**. A rename plays no sound. One that was renamed or moved again since says "Can't undo: Plan moved again"; when a new file took the name it goes back to, "Can't undo: a file named Draft is there now". Deletes and renames made in Finder are not in the list. After a page-title rename the cursor is in the title, so `⌘Z` there undoes the typing; the toast's **Undo** undoes the rename. The app finds a trashed item only by an exact name, its own or the one the Trash gives a clash ("Plan.md 01-30-05-828.md"), and never lists the Trash, so a big Trash does not slow a delete: when the Trash gave it any other name, that delete has no **Undo**.
- **Sounds, as in Finder**: when items land — a paste, a drag into a folder or the root, a drop from Finder, an undo or a redo of a move — the Mac plays its "Volume Mount" sound, once for the whole gesture. When items go to the Trash — **Delete**, or **Remove from vault** in the box after a drag out — it plays "drag to trash", once. Nothing plays when nothing landed, when a move fails, or when a drop is refused. The sounds follow System Settings › Sound › **Play user interface sound effects**: off there, off here
- **Back and Forward** (YAZ-3647): the ← → at the left of the tab row, `⌘⌥←` / `⌘⌥→` (Window › Back / Forward; change them in Settings › Hotkeys) and a mouse's back and forward buttons walk ONE list for the whole window: every page, tab and zoom level that came to the front, in order — a link, the sidebar, a tab click, `⌃Tab`, the tab board, a closed tab's neighbour, a zoom. A background tab joins the list when you go to it. Back to a page shows it in the tab you saw it in, at the level you left it, even when that tab shows another page now; another copy of the page keeps its own bullet. A new step after Back clears Forward. A closed tab's steps leave the list (Recently closed brings the page back), a renamed page keeps its steps, and a deleted one leaves them. The list keeps the last 100 steps and starts empty after a restart; each window has its own. Right-click ← or → — or hold the mouse down on it — for the list of the steps that way, the nearest 15 first, each "page › bullet"; pick one to go straight there (YAZ-3647 E3); a row whose step a closed tab or a deleted page took away while the list is open is grey and does nothing (YAZ-4156). The new tab is always a new copy, also when another tab shows the page, and it starts at that place's bullet; it goes next to this tab or at the end, as Settings › Files & Links › **Open new tabs** says (YAZ-4156). A ⌘- or middle click on a row keeps the list open, so you can open several places one after the other; a ⇧-click or a plain click closes it. Window › **Open Back in New Tab** and **Open Forward in New Tab** do the ⌘-click from the keyboard: they have no key until you give one in Settings › Hotkeys. The tooltip of ← and → names these clicks: "⌘-click: open in a new tab" and "Right-click or hold: history". A bullet whose page has not shown since a restart shows its page name alone. A sidebar click that moves the preview tab to another page is a step too: Back brings the first page back in that tab (E7). A page that Back, Forward or a new tab brings back leaves the right panel if the panel shows it: a page is never open in both areas (YAZ-4196). The right panel keeps its own ← →.
- **Tabs and windows**: notes — and folders — open in tabs (`⌃Tab` / `⌃⇧Tab` or `⌘⇧]` / `⌘⇧[` to switch, `⌘W` closes the **tab** — on the last one it empties the window and then closes it). `⌘⇧N` opens a new window in front on the same vaults, on a blank tab with the caret in the search, as `⌘T` — no tab is copied (YAZ-3343); it starts with every folder closed and, with two or more vaults, every vault row closed, and the vault keeps its open folders for its other windows (YAZ-3487 D17). ## Folders

A **folder is a page**. Right-click a folder in the sidebar → **Open folder page** (or press Enter on it) and it opens as a tab: its title (edit it to rename the folder — the folder on disk takes the title in kebab-case), the folder's own properties, a database view over its notes, the folder's own comments, and the notes that link to it. A single click still just selects and folds the folder. Its rows are the markdown notes under it, at any depth, plus its shortcuts (below) — not its subfolders, which are pages of their own, and not other kinds of file. **The vault itself is a page too** (YAZ-4921): right-click the blank space under the tree → **Open folder page** (the first item), or right-click the vault's name at the top of the sidebar → **Open folder page**, and the vault's own folder page opens as a tab. With two or more vaults in the window, right-click a vault's row instead (the blank space under the tree is no one vault's). It is a folder page like any other: its title is the vault's folder name (or the `title:` you give it — the folder on disk is never renamed), its rows are every note in the vault, a Folder group starts at the top folders, Other files lists the files at the root, "+ New" makes a note at the root, and its page file is `<vault>/.folder.md`, made on the first change. With "Show folder page files" on, it is the first row of the Files tree.

A folder's settings — its views, columns, labels and formulas, with the folder's own properties and comments beside them — live in a hidden `.folder.md` inside the folder, so they travel with it when it is renamed, moved or synced. Every folder has the file from the moment it exists, holding the folder's id and, for a folder made in the app, its title; its settings are added the first time you change something.

- **Views**: Table and Board (kanban) by default; the **+** at the end of the tabs adds Table, Board, Calendar, Cards, List or Page. Click a tab to switch, drag it to reorder, right-click it to rename, duplicate or delete. A Calendar's **Hide weekends** shows Monday to Friday: a Saturday's or Sunday's cards sit on the Friday before (on the next Monday when that Friday is off the grid), marked Sat or Sun, and a date no calendar has goes to "No date". The day names wear the **Header row** look (View tab › Layout › Header row [Aa ▾], or right-click the day names). **Default view** is in the page ⚙ › Views (YAZ-4909). **Start date** and **End date** (View tab › Calendar, YAZ-4858): with an End date column, a card that ends after its start is one bar over its days (it goes on in the next row at the week's edge). A table's Name cell is plain text, not a link: a click selects it, a double-click edits the note's title, Enter opens the note, ⌘-click opens it in a background tab and ⌥-click in the right panel. On any other cell Enter edits it, and ⌘Enter or ⌥Enter open the row's note (YAZ-4605). Right-click a row or card for the page menu; a table row's starts with **Open**.
- **Mini window** (YAZ-4547, YAZ-4605): right-click a row or card › **Open in mini window ⇧↩**, or press ⇧Enter on a cell or card, to edit the note in a small card over the folder page. ‹ › step through the rows in the order shown. With the mini window open, ⇧Enter on another row shows that row in it. Settings › Folder pages › **Keep the mini window pinned** keeps it open on a click outside it; a click in a menu the card itself opened never closes it. The card stays open when you rename the folder or the view tab.
- **Edit a table like a sheet** (YAZ-4612): ⌘Z and ⇧⌘Z undo and redo value changes on the folder page (typing, paste, fill, clear, Set value, New row below; a bulk change is one step). A toast's Undo is the same step as ⌘Z, so the two stay in step, and a step follows a note you rename. ⌘C then ⌘V inside the app's tables keeps a link as stored, so an ID link stays an ID link. Type on a cell to edit it with that letter; Tab and ⇧Tab move across, and Enter after an edit moves down. Delete or Backspace clears the selected values. With two or more cells selected, a small chip at the bottom right of the table shows Count, and Sum and Average for numbers; it floats over the rows, so nothing moves. A drag select scrolls at the table's edge. Clearing more than 50 cells, or deleting more than 10 notes, asks first. A pasted value that a Select column does not have is skipped, and a note says how many.
- **New row below** (YAZ-4611): right-click a table row › **New row below** makes a note with that row's group values, the view's filter values and its values in the sort columns, so it shows next to the row; its name is ready to type (Enter keeps it, Esc leaves "Untitled"), and the toast's Undo moves it to the Trash.
- **New**: the toolbar's New button (or a group header's "+") creates a note in the folder, titled `Untitled` every time (the ids keep the files apart), and so does "New note" on the folder in the sidebar. Both start from the folder's template when it has one: a hidden `.template.md` in the folder.
- **Built-in columns**: a Table shows the note's title under **Name** — its file name is a separate column, **File name**, that a view can add — and a `#` that counts from 1 inside every group (Columns and view › View › Row numbers, or right-click the `#` header, to hide it). A new folder has no columns of its own (no default Status). A column is never written into your notes as an empty key: a note gets the key when you give it a value, and until then the cell is simply empty.
- **Columns**: right-click a Table header to rename it, hide it, add a column to its right or delete it; drag a header to reorder. A rename changes only what the header says — the key stays. The Columns tab is two-level: the list shows, hides and reorders; open a row to edit its title, key, type, options, relation and (on a Board) card styling. Delete asks first: **Delete column and clear N values** removes the column from this folder and every page under it, and its value from each note under the folder (for a separate column, this page's values); **Keep the values in the notes** keeps the fields, which then show under "Other properties". Only a folder's own column can be deleted; a parent's column can be hidden. A rename, a type change and a delete each show a toast with Undo; a delete's one Undo puts back the column, the views here and below, and every value it cleared. Every Undo on a folder page takes back only its own change, so a sort or a view you made since stays. A new column's name cannot start with `file.`, `formula.` or `note.`, the built-in columns' prefixes. Renaming a Select option renames that value in every note under the folder that defines the column, and in the view filters that name it on the pages that show it (a read-only note is skipped); its Undo puts each note's exact value back.
- **Linked mentions column** (YAZ-4738): "+ Add column" › **Linked mentions** shows, for each row, the notes and folders that link to its page, as pills (3, then "+N"); a click opens one. It is worked out from the links, never stored, so it is read only. It sorts by count and filters by "is empty", "is not empty" and "contains". Edit column's **Only from the column** and **Only from the folder** count only the links held in one field, or only the links from notes under one folder. It flows down like any column.
- **Shortcuts**: a note lives in one folder but can also appear in others. Right-click a folder → **Add note shortcut** and pick the note: it then shows in that folder's views and under it in the sidebar, marked as a shortcut. It is the same note wherever it shows, so an edit anywhere edits the one file, and its values are its own fields, the same in every folder (a "Separate value" column keeps that folder's own). Right-click the shortcut → **Remove shortcut** takes it out of that folder and leaves the note where it lives. The note records it as `also_in`, by the folder's id, so renaming or moving either one never breaks it.
  - **On a folder page's row** (YAZ-4797): right-click a note row. A shortcut row has **Go to where it lives (<folder>)** and **Remove shortcut from <this page>** (the note stays where it lives). Every note row has **Add shortcut to ›**: the vault's folders with a search box, less the folders that already show the note. Hover the ↗ on a shortcut row to see where it lives. Each add and remove offers Undo.
- **No counts**: a folder row in the sidebar shows no note count (YAZ-2631); the Inbox row's due number is the one count that stays.
- **Links to folders**: `[[Folder title]]` links to a folder when no note answers to that name: a click opens the folder's tab, `[[` offers folders as you type, and renaming a folder updates the links to it. A link column can be pointed at a folder so its picker offers only that folder's notes.
- **Property declarations** (optional): a vault-wide `properties.json` decides which editor a column gets when the folder itself does not say. It is written INTO the vault, at `<vault>/.yaseendocs/properties.json` — the `.obsidian/`-style dotfolder that travels with your notes, so the declarations move with the vault rather than living in app state.

## Out of scope

Tags stay plain text (not resolved into links); `[[wikilinks]]`, by contrast, are live — they resolve, they are clickable, they autocomplete as you type `[[`, and they are rewritten when a note is renamed. There is no browser mode: the app runs only inside Electron. The file layer has no path jail: anything under your user account can be read or written. Distribution is deliberately minimal (locked decisions): no Developer-ID signing or notarization, no automatic install on Windows (it shows the update and links to the download), no Intel or universal Mac builds, no Linux — all Future issues.

Retired in YAZ-844: Obsidian's `.base` file format. There is no "New base", no `.base` file type, no `![[X.base]]` embed and no ` ```base ` code block — a folder's own page is the only place these views are mounted now.
